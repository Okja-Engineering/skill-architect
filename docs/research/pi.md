2. ### 4a. Correction — Cursor has a stock skills system

The Cursor cells above read "`.mdc` rules + `AGENTS.md`, no skills system", citing `rec:100,102`. Wrong, and wrong by omission: `rec:100` (agnix `CUR-*`) and `rec:102` (always-on / dynamic / packaging) **never mention Cursor skill roots**; that silence was read as absence. Cursor natively discovers `SKILL.md` from **four roots** — `.agents/skills/`, `.cursor/skills/` (project), `~/.agents/skills/`, `~/.cursor/skills/` (user) — and "for compatibility … also loads skills from Claude and Codex directories: `.claude/skills/`, `.codex/skills/`, `~/.claude/skills/`, and `~/.codex/skills/`" `[O]` cur:65-68,78. Each root is walked recursively, and a `.cursor/skills/` or `.agents/skills/` folder **anywhere in the repo** is picked up and auto-scoped to that subtree `[O]` cur:107,127,139.

We already presupposed it: `cts:113` enumerates `cursor.skill.source` = `workspace|user|builtin|plugin|claude` (`claude` **is** the compatibility root), and U-02/U-06 name `.cursor/skills/*/SKILL.md` `[O]` open-unknowns.md:29-35,81-89. Three activation modes are documented — agent-decided ("presented with available skills and decides when they are relevant"), manual `/skill-name` attaching to one message, Custom Mode for the whole session; `disable-model-invocation: true` restricts to explicit `/` `[O]` cur:27,29,175,214,218. `[I]` These map 1:1 onto `cursor.skill.trigger` = `agent_read|manually_attached|skill_name_in_prompt`; `agent_read` is **weak evidence** that the agent-decided path is a file read — what U-02 must confirm, not assume.
