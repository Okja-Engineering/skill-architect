## Goal
Five rules that fail CI on a seeded violation and pass once it is removed. Pure enforcement — this half of the old S8 needs no attribution, no docs and no user answer, which is what keeps **both** minimum viable epics closed.

**Why the split.** Round 1's single S8 depended on **S3**, because it also wrote the docs that describe attribution. The fallback MVE (SP1 = no) withdraws S3 — and therefore did not close. The guardrails never needed attribution to exist; the docs did. Splitting on that seam is the fix. `S8b` carries the documentation half.

**Round-3 correction:** rules 2 and 3 each stated a rule broader than the mechanism that enforces it. A guardrail whose rule text overreaches its grep is worse than no guardrail — it reads as proof and is not.

**Round-4 corrections.** (a) **Rule 1 shipped red** (C4-#1): its grep covered `tests/` and a `scripts/` directory that does not exist, and `tests/test_skill.sh:23` and `tests/test_walk.sh:25` **already invoke `python3`**. It is now scoped to the width of the rule it cites. (b) **Rule 2's seeded violation had no stated home** and `go/parser.ParseDir` reads `_test.go` files by default (V4-#12). (c) **Rule 5 is new**: the token single-writer invariant had no enforcement anywhere in the epic (V4-#9, V4-#1).

**Round-5 correction — the one that matters (V5-#1, V5-#2, HIGH ×2).** Rule 5 shipped **red on the day it merged**, because round 4 wrote it at *repo* width while D12's justification and this epic's file scope are *Cursor* width. The rule's own mechanisms were never executed against `main` before the DoD claimed red→green. They have been now, and the results are stated below as executed baselines. **The governing invariant, which every rule in this file is now written to: the guardrail's width, the contract's admissible-source set, and the set of files this epic owns are one set — and no rule may claim red→green until its command has been run against `main` and its result recorded here.**

## Guardrail rules (grep + `go/ast` + Go tests — not semgrep)
1. **No `python3` invocation in a skill script.** Mechanism: `grep -rn 'python3' skills/*/scripts/`. **Scoped, deliberately, to what `AGENTS.md:6` actually says** — *"Do not introduce Python for skill scripts"* — because the repo-wide reading ships red: `tests/test_skill.sh:23` and `tests/test_walk.sh:25` both invoke `python3` today to parse the four plugin manifests, and `skills/*/scripts/` is **clean** (baseline above). Two consequences, stated rather than papered over: the rule ships **green** and stays green as skills are added; and it does **not** cover `tests/`. Widening it to `tests/` requires first removing those two invocations (each is a `python3 - <<PY` heredoc doing `json.load` + three asserts, replaceable with `jq`, which CI already has via `skill-validator`'s toolchain) — **no slice in this epic owns that removal**, it is recorded as residue **H1** in `roadmap.md`, and the rule text here must not imply otherwise. `scripts/` is not in the grep because no such directory exists (`ls scripts` → exit 2).
2. **No mislabelled estimate.** A `MetricResult` built as `present` with a `Source` **other than** `estimated`, **in the body of** a function whose name matches `(?i)estimate`. **Rewritten at the spec gate:** the old rule forbade `present` outright from an `estimate*` function, which forbade exactly what Fork (vi) option 2 mandates — a direct design conflict. The rule forbids the **mislabel**, not the state.
   **Mechanism, and the rule narrowed to match it:** `TestNoMislabelledEstimate`, a **`go/ast` walk** in `profiler/guardrails_test.go`. Parse the package with `go/parser.ParseDir`, **passing a filter that excludes `_test.go` files** (`func(fi fs.FileInfo) bool { return !strings.HasSuffix(fi.Name(), "_test.go") }`) — without it the walk reads its own test fixtures and any seed committed there makes CI red forever (V4-#12). For every `*ast.FuncDecl` whose `Name.Name` matches `(?i)estimate`, walk its body for composite literals of **`RawMetricResult`, `TokenResult`, `ToolCallResult`, `ActivationResult`, `TimingResult`, `AttributionResult` and `ContextResult`** — the seventh added because SC-a item 5 creates it and a token-adjacent result type outside the walk is exactly the gap this rule exists to close — and for calls to the `Present*Result` constructors; fail if `State` is `MetricPresent` while `Source` is any value other than `SourceEstimated`. **Baseline: the repo has no `(?i)estimate`-named function today, so the walk has nothing to fire on and ships green** — verified with `grep -rn 'func [a-zA-Z]*[Ee]stimate' profiler/` → 0.
   **Where the seed lives:** the red→green harness in `tests/test_guardrails.sh` writes `profiler/zz_guardrail_seed.go` — a **non-test** file containing `func estimateBogus() TokenResult { return PresentTokenResult(TokenCounts{}, string(SourceHooks)) }` — into a scratch copy of the tree, runs `go test -run TestNoMislabelledEstimate ./profiler`, asserts non-zero, deletes it, asserts zero. Nothing is committed.
   Round 2's rule text said "inside **or returned from**"; a body walk catches `return PresentTokenResult(v, SourceHooks)` because the call is *in* the body, but it does **not** catch `return buildResult()` where the mislabel lives in a helper with a non-matching name. **That gap is the rule's boundary, not a bug in it:** the rule says "in the body of", the gap is documented in `S8b`'s doc, and the mitigation is naming convention. If a reviewer judges the AST walk too much machinery for one rule, the sanctioned fallback is to **drop rule 2 to a documented manual check in `S8b`'s doc** and say so in the PR; what is not acceptable is an unnamed mechanism, or a rule wider than its grep.
3. **No caller of the raw spool appender outside `hooks.go` and `privacy.go`** (V5-#6 — round 4's heading was "no unredacted payload on the write path", which is the *property* the rule buys, not the rule; a grep for callers of one private function cannot see an unredacted payload, and a heading that claims it reads as proof and is not). Mechanism, stated against the two function names S1a pins: `appendSpoolLine` is package-private and raw; `WriteHookEvent` is the exported entrypoint that redacts (S4) and then calls it. The rule is **`grep` for callers of `appendSpoolLine` outside `profiler/hooks.go` and `profiler/privacy.go`** (R-CS-18/19). **Round 2's rule was "every call site that appends to the spool goes through S4's redactor", which S11's `serve.go` violates by construction** — a second sink must append, so a rule phrased against *appending* fires on a legitimate caller (V3-#11). Naming the two functions dissolves it without an exception list: `serve.go` calls `WriteHookEvent`, which is redacted, so the grep never sees it. **The property the rule buys — "nothing unredacted reaches disk" — is proven by S4's own `privacy_test.go` grep against a written spool file, not here.** S11's DoD is written to this contract, and if a future sink calls the raw appender the rule catches it.
4. **No `cursor.` literal outside the two places D5 allows** — `profiler/cursor_wirekeys.go` and `*_test.go` files. Mechanism: `grep -rn 'cursor\.' profiler/ --include='*.go'` minus those two. Test files are included in the allowance because fixtures must spell wire keys; **D5 states both**, so this file and the roadmap agree. Per D4, S10 emits no `cursor.*` string at all, so there is no S10 conflict. **This rule is why S0 is a dependency:** the baseline above is **12** live `cursor.` literals in `cursor.go` — eight event/metric names and **four inside `Unknown*Result` reason strings** — and CI would be red from the moment this slice merged until S0 relocates all twelve.
5. **One writer for `Profile.Tokens` on the Cursor path, and `hooks` is never a token-flow label there (V4-#1, V4-#9, V5-#1, V5-#2, D12).** D12 states both invariants; round 3 enforced neither and round 4 enforced them at a width that ships red. **Both mechanisms are scoped to the Cursor-path file set defined above — the files this epic owns — and to SC-a item 8's five-label allowlist. Neither ever reads `claude_code.go`, `codex.go` or `devin.go`.** Two mechanisms, both seeded red→green:
   - **(a) single writer, `grep`:** `grep -n '\.Tokens[[:space:]]*=' "${CURSOR_PATH_FILES[@]}"` minus `profiler/tokens_select.go` (SC-a's home for `ApplyTokenSelection`, the one function that contains the assignment) and `*_test.go` returns **zero** lines. Baseline: **6** on `main`, all in `cursor.go`; **0** once S0 merges, which is a declared dependency. Seed: a `p.Tokens = …` line added to a scratch copy of `cursor.go`.
   - **(b) no inadmissible token-flow label, `go/ast`: `TestNoHooksTokenLabel`** (V5-#7 — round 4 named no test function). In the same non-test walk as rule 2, **restricted to the Cursor-path file set**, fail on any `TokenCandidate` composite literal or `PresentTokenResult` call whose `Source` is **`SourceHooks`**. Baseline: **0** on `main`. Seed: a `TokenCandidate{Source: SourceHooks}` literal in the scratch `zz_guardrail_seed.go`.
     **Why the banned set is `hooks` and only `hooks`.** SC-a item 8's admissible-source set for a token-flow candidate is the five ranked labels `server_api|otel|otel_aggregate|mcp_reported|estimated`. On the Cursor-path file set, `hooks` is the only member of the complement a slice can construct with a reason to: S1b and S5 read a hook spool, and D12's justification — no hook event reports input/output/cache flow for a model call, ledger Q1:300 — is exactly about them. `session_data` and `sqlite` label other adapters' surfaces this epic does not own, and `claude_code.go:465`'s `SourceSessionData` is **legitimate** (SC-a item 15 maps it to `harness_reported`), so banning them package-wide made the guardrail contradict the contract (V5-#2). `none` and `""` never appear as a `PresentTokenResult` argument or a `TokenCandidate` literal — they are what `Unknown*Result`/`ErrorTokenResult` leave behind — so the *runtime* rule that catches them is **SC-a item 12 rule (b)**, `ValidateProfile`, which runs on every profile of every adapter. Denylist and allowlist therefore coincide on this file set, which is the invariant this round was called to restore.
   SC-a's `contract_test.go` already refuses an inadmissible candidate at runtime; this rule catches it at the source level, in slices whose tests may never construct one. Both mechanisms bind only to SC-a and S0, both already dependencies — no new edge.

## Test approach
`tests/test_guardrails.sh` (new): for rules 1, 3, 4 and **5(a)**, seed a violation in a **scratch copy** of the tree, assert the check exits non-zero, remove it, assert it exits zero — red→green per rule, so each guardrail is proven to catch something rather than merely existing. Rule 1's seed is a `python3` line added to a scratch copy of `skills/skill-audit/scripts/check-paths.sh`; rule 3's is a new file calling `appendSpoolLine` directly; rule 4's is a `cursor.` literal added to a **reason string** in `cursor.go`, not just to a `const` block, because that is the shape S0 had to fix; rule 5(a)'s is a `p.Tokens = ...` line in `cursor.go`. Rules 2 and **5(b)** are `profiler/guardrails_test.go` — `TestNoMislabelledEstimate` and `TestNoHooksTokenLabel`, the `go/ast` walks above — driven by the same scratch-copy seed file (`profiler/zz_guardrail_seed.go`), **never a committed `_test.go` fixture**, which the `ParseDir` filter would ignore and a committed non-test seed would make CI permanently red (V4-#12).
**Every rule's baseline is re-run in this PR and the output pasted into the PR body**, against the tree as it stands at merge — the step round 4 skipped and V5-#1/#2 caught. A rule whose baseline does not match the table above does not merge.
**No `ci.yml` edit is required (V4-#7, C4-#1).** S1a DoD 7 replaces the workflow's four named script steps with one `tests/test_*.sh` glob, so this slice's script is discovered on merge and rule 2/5(b)'s Go tests run under the existing `go test ./...` step.
