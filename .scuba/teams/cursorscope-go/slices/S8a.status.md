## Goal
Five rules that fail CI on a seeded violation and pass once it is removed. Pure enforcement — this half of the old S8 needs no attribution, no docs and no user answer, which is what keeps **both** minimum viable epics closed.

**Why the split.** Round 1's single S8 depended on **S3**, because it also wrote the docs that describe attribution. The fallback MVE (SP1 = no) withdraws S3 — and therefore did not close. The guardrails never needed attribution to exist; the docs did. Splitting on that seam is the fix. `S8b` carries the documentation half.

**Round-3 correction:** rules 2 and 3 each stated a rule broader than the mechanism that enforces it. A guardrail whose rule text overreaches its grep is worse than no guardrail — it reads as proof and is not.

**Round-4 corrections.** (a) **Rule 1 shipped red** (C4-#1): its grep covers `tests/` and a `scripts/` directory that does not exist, and `tests/test_skill.sh:23` and `tests/test_walk.sh:25` **already invoke `python3`** — executed at the round-4 gate, both confirmed — so its red→green DoD was unsatisfiable on the day it merged. It is now scoped to the width of the rule it cites. (b) **Rule 2's seeded violation had no stated home** and `go/parser.ParseDir` reads `_test.go` files by default, so the obvious seed — a fixture function in `guardrails_test.go` — would have made CI permanently red (V4-#12). (c) **Rule 5 is new**: the token single-writer invariant had no enforcement anywhere in the epic (V4-#9, V4-#1).

## Guardrail rules (grep + `go/ast` + Go tests — not semgrep)
1. **No `python3` invocation in a skill script.** Mechanism: `grep -rn 'python3' skills/*/scripts/`. **Scoped, deliberately, to what `AGENTS.md:6` actually says** — *"Do not introduce Python for skill scripts"* — because the repo-wide reading ships red: `tests/test_skill.sh:23` and `tests/test_walk.sh:25` both invoke `python3` today to parse the four plugin manifests, and `skills/*/scripts/` (six scripts under `skill-audit` and `skill-rewrite`) is **clean**, verified by running the grep at the round-4 gate. Two consequences, stated rather than papered over: the rule ships **green** and stays green as skills are added; and it does **not** cover `tests/`. Widening it to `tests/` requires first removing those two invocations (each is a `python3 - <<PY` heredoc doing `json.load` + three asserts, replaceable with `jq`, which CI already has via `skill-validator`'s toolchain) — **no slice in this epic owns that removal**, it is recorded as Known residue in `roadmap.md`, and the rule text here must not imply otherwise. `scripts/` is not in the grep because no such directory exists (`ls scripts` → exit 2).
2. **No mislabelled estimate.** A `MetricResult` built as `present` with a `Source` **other than** `estimated`, **in the body of** a function whose name matches `(?i)estimate`. **Rewritten at the spec gate:** the old rule forbade `present` outright from an `estimate*` function, which forbade exactly what Fork (vi) option 2 mandates — a direct design conflict. The rule forbids the **mislabel**, not the state.
   **Mechanism, and the rule narrowed to match it:** a **`go/ast` walk** in `profiler/guardrails_test.go`. Parse the package with `go/parser.ParseDir`, **passing a filter that excludes `_test.go` files** (`func(fi fs.FileInfo) bool { return !strings.HasSuffix(fi.Name(), "_test.go") }`) — without it the walk reads its own test fixtures and any seed committed there makes CI red forever (V4-#12). For every `*ast.FuncDecl` whose `Name.Name` matches `(?i)estimate`, walk its body for composite literals of **`RawMetricResult`, `TokenResult`, `ToolCallResult`, `ActivationResult`, `TimingResult`, `AttributionResult` and `ContextResult`** — the seventh added because SC item 5 creates it and a token-adjacent result type outside the walk is exactly the gap this rule exists to close — and for calls to the `Present*Result` constructors; fail if `State` is `MetricPresent` while `Source` is any value other than `SourceEstimated`.
   **Where the seed lives:** the red→green harness in `tests/test_guardrails.sh` writes `profiler/zz_guardrail_seed.go` — a **non-test** file containing `func estimateBogus() TokenResult { return PresentTokenResult(TokenCounts{}, string(SourceHooks)) }` — into a scratch copy of the tree, runs `go test -run TestNoMislabelledEstimate ./profiler`, asserts non-zero, deletes it, asserts zero. Nothing is committed.
   Round 2's rule text said "inside **or returned from**"; a body walk catches `return PresentTokenResult(v, SourceHooks)` because the call is *in* the body, but it does **not** catch `return buildResult()` where the mislabel lives in a helper with a non-matching name. **That gap is the rule's boundary, not a bug in it:** the rule says "in the body of", the gap is documented in `S8b`'s doc, and the mitigation is naming convention — a helper that builds an estimate should itself match `(?i)estimate` and is then covered. If a reviewer judges the AST walk too much machinery for one rule, the sanctioned fallback is to **drop rule 2 to a documented manual check in `S8b`'s doc** and say so in the PR; what is not acceptable is an unnamed mechanism, or a rule wider than its grep.
3. **No unredacted payload on the write path.** Mechanism, stated against the two function names S1a pins: `appendSpoolLine` is package-private and raw; `WriteHookEvent` is the exported entrypoint that redacts (S4) and then calls it. The rule is **`grep` for callers of `appendSpoolLine` outside `profiler/hooks.go` and `profiler/privacy.go`** (R-CS-18/19). **Round 2's rule was "every call site that appends to the spool goes through S4's redactor", which S11's `serve.go` violates by construction** — a second sink must append, so a rule phrased against *appending* fires on a legitimate caller (V3-#11). Naming the two functions dissolves it without an exception list: `serve.go` calls `WriteHookEvent`, which is redacted, so the grep never sees it. **S11's DoD is written to that contract**, and if a future sink calls the raw appender the rule catches it.
4. **No `cursor.` literal outside the two places D5 allows** — `profiler/cursor_wirekeys.go` and `*_test.go` files. Mechanism: `grep -rn 'cursor\.' profiler/ --include='*.go'` minus those two. Test files are included in the allowance because fixtures must spell wire keys; **D5 states both**, so this file and the roadmap agree. Per D4, S10 emits no `cursor.*` string at all, so there is no S10 conflict. **This rule is why S0 is a dependency:** `profiler/cursor.go:175,182,184,186,197,216,224,234,242,250,262,271` holds **12** live `cursor.` literals today — eight event/metric names and **four inside `Unknown*Result` reason strings** — and CI would be red from the moment this slice merged until S0 relocates all twelve.
5. **One writer for `Profile.Tokens`, and `hooks` is never a token-flow label (V4-#1, V4-#9, D12).** D12 states both invariants and round 3 enforced neither, in any slice — five producers were asked to honour a convention. Two mechanisms, both seeded red→green:
   - **(a) single writer, `grep`:** `grep -rn '\.Tokens[[:space:]]*=' profiler/ --include='*.go'` minus `profiler/tokens_select.go` (SC's home for `SelectTokenSource`) and `*_test.go` returns **zero** lines. Seed: an assignment added to a scratch copy of `cursor.go`.
   - **(b) no `hooks` flow label, `go/ast`:** in the same non-test walk as rule 2, fail on any `TokenCandidate` composite literal or `PresentTokenResult` call whose `Source` is `SourceHooks`, `SourceSessionData`, `SourceSQLite`, `SourceNone` or `""`. Seed: a `TokenCandidate{Source: SourceHooks}` literal in the scratch `zz_guardrail_seed.go`.
   SC's `contract_test.go` already refuses such a candidate at runtime; this rule catches it at the source level, in slices whose tests may never construct one. Both mechanisms bind only to SC, which is already a dependency — no new edge.

## Test approach
`tests/test_guardrails.sh` (new): for rules 1, 3, 4 and **5(a)**, seed a violation in a **scratch copy** of the tree, assert the check exits non-zero, remove it, assert it exits zero — red→green per rule, so each guardrail is proven to catch something rather than merely existing. Rule 1's seed is a `python3` line added to a scratch copy of `skills/skill-audit/scripts/check-paths.sh`; rule 3's is a new file calling `appendSpoolLine` directly; rule 4's is a `cursor.` literal added to a **reason string** in `cursor.go`, not just to a `const` block, because that is the shape S0 had to fix; rule 5(a)'s is a `p.Tokens = ...` line in `cursor.go`. Rules 2 and **5(b)** are `profiler/guardrails_test.go`, the `go/ast` walk above, driven by the same scratch-copy seed file (`profiler/zz_guardrail_seed.go`) — **never a committed `_test.go` fixture**, which the `ParseDir` filter would ignore and a committed non-test seed would make CI permanently red (V4-#12).
**No `ci.yml` edit is required (V4-#7, C4-#1).** S1a DoD 7 replaces the workflow's four named script steps with one `tests/test_*.sh` glob, so this slice's script is discovered on merge and rule 2/5(b)'s Go test runs under the existing `go test ./...` step. Round 3 listed `.github/workflows/ci.yml` in this slice's Files while three other bash-test-adding slices did not — the glob makes the wiring uniform instead of per-slice.
