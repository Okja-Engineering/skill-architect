## Goal
Hooks become a first-class source alongside the OTel export file, and `experiment plan` / `experiment run` can drive a hook-sourced capture, closing the loop back to F04.

## Definition of done
1. `Probe()` reports hooks **and** OTel for the same metric via `Capability.Available map[MetricName][]MetricSource`, while `Capabilities` names the single source it will actually use. **This was proven impossible before SC:** `Capabilities` is `map[MetricName]MetricSource` (`types.go:54`), so a second assignment silently overwrote the first and "reports hooks and OTel independently" was unassertable. S7 does not own `types.go`; SC does.
2. `Condition` / `ExperimentStep` carry a `HookSpool` path (R-SA-15).
3. `profiler compare` on two hook-sourced profiles returns `comparable: true` for `tool_calls` **and** `skill_activation`, with **both** sides' sources present in the report (SC's `BaselineSource`/`CandidateSource`).
4. **Cross-encoding comparison is asserted, not assumed (C3-#2).** Round 2 claimed encoding-invariance held "even if one side is later re-captured from the OTel aggregate path" while S1b left `Status` empty on the hooks side and S0 carried it through on the OTel side — the two sides then had different `success_rate` denominators and the claim was false. Two changes make it true and this DoD tests it rather than asserting it: **S1b now always sets `Status`** (D11) and **SC defines `successes` exactly once** via a row-outcome rule that reads `Status` when set and falls back to `Success` only for pre-v1.1 rows. So a hooks-sourced profile and an OTel-aggregate profile of the same session compare to **zero delta** on `count`, `successes`, `failures`, `aborted` and `success_rate` — and this slice is where that is exercised end to end across two real adapters rather than two fixtures of one.

## Test approach
`profiler/unify_test.go` (new, this slice's own file):
- a probe test asserting two distinct sources are reported for one metric, and that `Capabilities` still names exactly one;
- a compare test over two hook-sourced fixtures asserting `comparable: true` for both metrics and both source labels in the output;
- **a cross-adapter mixed-encoding compare (DoD 4):** one profile captured through S1b's hook path (per-call rows, `Status` set from `postToolUse`/`postToolUseFailure`) against one through S0's OTel path (aggregate `Count` rows, `Status` from `cursor.tool.status`) for the same session, asserting zero delta on all five tool-call figures — with the fixture deliberately **heterogeneous** (mixed success / failure / aborted), because a homogeneous one cannot fail;
- an `experiment run` test driving a hook-spool condition end to end;
- an assertion that a retracted metric yields `unknown`-with-reason, never a silent zero;
- an assertion that `tokens` and `context_window` are compared as **separate** metrics with separate sources (D12), so a `preCompact`-derived occupancy number can never be differenced against a token-flow number.
§G14 flags that `CompareProfiles` has been read but never exercised against a hook-sourced profile — these tests are what convert that from assumption to fact. If they fail, S7 grows and R-SA-06 becomes a real constraint rather than a formality.
