- **Stage:** parked — **gated on User Question 3** (Fork vi)
- **Owner:** unassigned
- **Branch:** none (target: `epic/skill-scope`)
- **Depends on:** **SC-a** (the `estimated`/`mcp_reported` constants, `TokenCandidate`, `ContextResult`, `CaveatEstimatedFlow`), **SC-b** (its test approach asserts the cross-class refusal and `compareContextWindow`, both of which live in `compare.go`), **S1b** (the spool reader, the `tokens.go` stub, and the `enrich()` call site this slice registers into)

## Goal
Produce every hook-derived token number under a label that names its honesty, so no reader — and no comparison — can mistake any of them for billed tokens. SC-a ships the *channels*, **the rank, the allowlist and the assignment site**; SC-b ships the *comparison rules that refuse to difference them dishonestly*; this slice ships the *producers that read a spool*.

**The old dep on S3 was phantom** and is removed: token extraction needs no attribution, and parking S5 behind the slice most likely to collapse (S3, gated on SP1) was invented sequencing.

**Retitled at round 3, re-scoped at round 4.** "Four sources, four labels" was unimplementable as written: a `TokenResult` has exactly **one** `Source` (`types.go:23`; `profiler-spec.md:36`), so four labels cannot ride one `TokenCounts` — that is **D12**. Round 3 put `selectTokenSource` in this slice; the round-4 sweep found **five** token producers, not three, and **S0 is among them and ships earlier, inside the MVE, gated on nothing** (V4-#1). A single-writer function cannot be owned by a slice that its writers do not depend on, so the selector moved to the contract slice. What stays here is everything that reads a spool: the two hook-derived candidates, the caveat, and the spec-doc record.

**Corrected at round 5 (V5-#3).** "Assigns `Profile.Tokens` nowhere" was true and insufficient — round 4 left the assignment homeless. The wording is now the one the whole epic uses: **this slice registers candidates and calls nothing that assigns.** The call site it registers into is S1b's, at the end of `enrich()`.

## Definition of done

**Part 1 — the two quantities are separated (D12).** Context-window occupancy is not token flow, and conflating them is what created the four-labels problem:

| Metric | Carrier | Supplier | Label | Class (D3) |
|---|---|---|---|---|
| `context_window` | SC-a's `ContextResult` (`ContextTokens`, `ContextWindowSize`, `ContextUsagePercent`) | `preCompact` — all three fields, ledger §A5.1:136 | `hooks` | harness_reported |
| `tokens` | `TokenCounts` (unchanged from v1) | a candidate, ranked by SC-a's selector | that source's label | that source's class |

1. **`context_window` is `present` with `Source: "hooks"`** from `preCompact`'s three fields, landing in SC-a's `ContextResult`, and is **absent** (nil pointer, omitted from JSON) when the session never compacted — never a zero-valued `present` (R-SA-02). This is the one metric this slice assigns directly, because it has one supplier and no competitor. The nil case it creates is the one SC-b item 10's comparator is written to handle (V5-#12).

**Part 2 — this slice registers two candidates and calls nothing that assigns.** The rank, the allowlist, the eligibility rule and the assignment all live in SC-a (`tokens_select.go`, items 8): **`server_api` (S9) > `otel` (S6) > `otel_aggregate` (S0, S6-fallback) > `mcp_reported` (here) > `estimated` (here)**, lower candidates **discarded, not merged**, unscoped candidates ineligible under `--session`. This slice `Add`s to the accumulator threaded through `enrich()`; **the one `ApplyTokenSelection` call on this path is S1b's, and it runs after `enrichTokens` returns** — which is exactly why this slice needs no call site and must not add one.

| Flow candidate registered here | Supplier | Label | Class | `SessionScoped` |
|---|---|---|---|---|
| `chars/4` over hook payloads — `beforeSubmitPrompt.prompt`, `postToolUse.tool_output`, `afterShellExecution.output`, `beforeReadFile.content`, `afterMCPExecution.result_json`, `afterAgentResponse.text`, `afterAgentThought.text` (ledger Q1:300) | the spool, scoped by `conversation_id` | `estimated` | estimated | **true** |
| `afterMCPExecution.result_json` → `usage`/`token_usage`/`tokens` (**External evidence** — cursorscope's probe, ledger §A5.1:142; not a documented Cursor field) | MCP server self-report, scoped by `conversation_id` | `mcp_reported` | self_reported | **true** |

Both are `SessionScoped: true` because every hook event carries `conversation_id` as a base field (§A5.1:113); neither needs the single-conversation escape, which exists for the OTel aggregates only (S0 DoD 3).

2. **The `estimated` candidate carries `Caveat: CaveatEstimatedFlow`** — SC-a's closed-set constant, whose declared text is *"chars/4 estimate; structurally undercounts billed input and omits the system prompt, the always-loaded skill listing and the cache split"*. The caveat rides in the profile, not only in the doc, so a downstream reader of the JSON sees it (C4-#3's carrier, applied to the second of D11/D12's two caveats).
3. **`hooks` is not an admissible token-flow label, and this slice must not emit one.** No hook event reports input/output/cache-read/cache-creation for a model call — ledger Q1:300 says so in those words, and the payload table §A5.1:117-137 bears it out. The only hook-derived flow number is the `chars/4` estimate, and it is labelled `estimated`. `hooks` appears on `context_window`, `tool_calls` and `timing`; never on `tokens`. SC-a's selector admits only the five flow labels and **refuses** a `hooks` candidate by name, and S8a's guardrail 5(b) greps for the shape across the Cursor-path file set — **which includes `tokens.go`, this slice's file**, so this is enforced twice and asserted once here.
4. **A `present` token result requires the chosen source to supply both `Input` and `Output`** — SC-a's rule, exercised here on this slice's own candidates: an MCP report carrying only `input_tokens` yields `unknown` with a reason naming the source and the missing field, never a `present` result with a zero standing in for "not supplied" (R-SA-02). `CacheRead`/`CacheCreation`/`Reasoning` are `omitempty` and simply absent when the source does not carry them.
5. No value produced by an `estimate*` function ever serializes with any other source (S8a's guardrail 2 enforces it; note that this slice is the first to give that guardrail a function to walk — the repo has no `(?i)estimate`-named function today). `docs/profiler-spec.md` records the structural undercount, that `preCompact` fires **only** on compaction (ledger §A5.1:141), and points at SC-a's rank order rather than restating it — one statement of the order, in the contract doc, is what keeps S0/S6/S9 from drifting from it.

## Test approach
`profiler/tokens_test.go` (new, this slice's own file):
- one fixture per candidate this slice registers, asserting its exact `Source` string **and** the honesty class SC-a maps it to;
- **a registration test, not a selection test:** a spool yielding both an `estimated` and an `mcp_reported` candidate produces `Source: "mcp_reported"` with **every** `TokenCounts` field from the MCP report and none retained from the estimate — exercised through the `enrich()` path, whose rank ladder is proven exhaustively in SC-a's own test. The assertions that belong here are that **this slice `Add`s both candidates, contains no assignment to `Profile.Tokens`, and adds no second `ApplyTokenSelection` call site** (V5-#3 — the negative half alone is satisfied by an inert file), plus a test that removing this slice's registration leaves the rest of the ladder intact;
- an assertion that the `estimated` candidate carries `CaveatEstimatedFlow` and that the caveat survives `Marshal→Unmarshal→Marshal`;
- a `preCompact` fixture asserting `context_window` is `present` with `Source: "hooks"` and all three fields populated, **and that `Profile.Tokens` is unaffected by it** — the assertion that proves D12's separation actually holds;
- a no-compaction fixture asserting `context_window` is **absent** rather than a zero-valued `present`;
- a fixture whose only candidate supplies `Input` but not `Output`, asserting `tokens: unknown` with the reason naming both (DoD 4);
- a negative test that a `hooks`-labelled flow candidate is **refused by SC-a's selector, by name** (DoD 3);
- a negative test that `compare` **refuses** `estimated` vs `server_api` (SC-b's cross-class rule), so an estimate can never be silently differenced against a billed number — the failure `compareTokens` allows today, where the baseline's source is dropped entirely (`compare.go:115`);
- an assertion that `context_window` and `tokens` land in **different** keys of `CompareProfiles`' metric map, using SC-b's new `compareContextWindow` (SC-b item 10) — the code **S7 DoD 5** and S7's last test bullet bind to (V5-#8: round 4 wrote "S7 DoD 25", and S7 has five DoD items).

The last two bullets are why this slice depends on **SC-b** as well as SC-a: both assert behaviour that lives in `compare.go`.
