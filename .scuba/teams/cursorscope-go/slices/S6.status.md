## Goal
Read `cursor.api.request.{input,output,cache_read,cache_creation}_tokens` per request and scope a capture by `cursor.conversation.id`, instead of throwing those fields away and summing a session-blind aggregate metric. All five keys are **Specification** (ledger §A5.2:152 for the join key, :166 for the four token attributes).

## Definition of done
1. Given an export containing two conversations, `capture --session <cursor.conversation.id>` returns tokens for **only** that conversation, and the scoped totals differ from the unscoped ones. This is supplied: `cursor.api.request` is a **log** event, and `cursor.conversation.id` is a documented log join key (ledger §A5.2:152).
2. **The aggregate fallback is unscopable, and the DoD now says what that costs (V3-#8).** `cursor.token.usage` is a metric whose only attributes are `cursor.token.type`, `cursor.model.name` (opt), `cursor.api.status` (opt) and `cursor.api.billable` (opt) — **there is no conversation id on it** (ledger §A5.2:158). So the fallback is **export-scoped, never session-scoped**, and the two cases split:
   - **no `--session`** → fall back to the aggregate, `Source: "otel_aggregate"` (the new `MetricSource` member SC adds), and the spec doc records that the number covers the whole export;
   - **`--session <id>` given, no per-request events** → `tokens: unknown` with the reason *"cursor.token.usage carries no conversation id; cannot scope to session `<id>`"*. **Not** a silently unscoped sum wearing a session's name, which is the R-SA-02 failure this epic exists to prevent.
   Round 2 said the fallback "labels the result `otel_aggregate`" and stopped there, which quietly permitted an export-wide total to be returned for a `--session` query. `cursor.model.name` is the only further scoping the metric permits, and this slice does not use it.
3. **The new `cursor.*` literals live in `profiler/cursor_wirekeys.go`** (D5). This slice therefore **owns that file jointly with S0**, which creates it in wave 2. Round 2 caught that S6's DoD requires new wire keys while its Files omitted the only file allowed to hold them, which made the slice unbuildable as scoped under S8a's guardrail 4.
4. Per D12, this slice does not assign `Profile.Tokens` directly: it registers an `otel` candidate with S5's `selectTokenSource`, which ranks it above `mcp_reported`/`estimated` and below `server_api`. On a capture where S5 is not present (Enterprise-only, hooks absent), it is the sole candidate and wins trivially.

## Test approach
`profiler/cursor_scope_test.go` (new, this slice's own file): a two-conversation export fixture asserting scoped totals; an aggregate-only fixture **without** `--session` asserting both the summed value **and** the `otel_aggregate` label; an aggregate-only fixture **with** `--session` asserting `unknown` and the exact reason string (DoD 2's second case — the assertion round 2 had no way to make); a mixed fixture (some requests scoped, some not) asserting the adapter prefers per-request and does not double-count; an assertion that an unknown `--session` yields `unknown`-with-reason, never a silent zero (R-SA-02). Fixtures spell `cursor.*` keys directly — the second place D5 allows is `*_test.go`.
