## Goal
Read `cursor.api.request.{input,output,cache_read,cache_creation}_tokens` per request and scope a capture by `cursor.conversation.id`, instead of throwing those fields away and summing a session-blind aggregate metric.

## Definition of done
1. Given an export containing two conversations, `capture --session <cursor.conversation.id>` returns tokens for **only** that conversation, and the scoped totals differ from the unscoped ones.
2. Absent per-request events, it falls back to the aggregate `cursor.token.usage` metric and labels the result `Source: "otel_aggregate"` — the new `MetricSource` member SC adds. The old DoD said the fallback "says so in `Source`", which was untestable: the enum had no aggregate member (`types.go:41-47`) and S6 did not own `types.go`. Now the fallback is visible **in the profile**, not only in prose, and a reader of a comparison report can tell a per-request number from a session-blind sum.

## Test approach
`profiler/cursor_scope_test.go` (new, this slice's own file): a two-conversation export fixture asserting scoped totals; an aggregate-only fixture asserting both the summed value **and** the `otel_aggregate` label; a mixed fixture (some requests scoped, some not) asserting the adapter prefers per-request and does not double-count; an assertion that an unknown `--session` yields `unknown`-with-reason, never a silent zero (R-SA-02).
