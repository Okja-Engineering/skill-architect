# S6 — Per-request tokens + conversation scoping (Enterprise OTel)

- **Stage:** parked — gated on User Question 2 (Cursor plan tier)
- **Owner:** unassigned
- **Branch:** none (target: `epic/skill-scope`)
- **Depends on:** **SC** (the `otel_aggregate` constant, and `SelectTokenSource` — which this slice calls), **S0** (creates `cursor_wirekeys.go`; owns the `extractCursor*` helpers this slice extends)
- **Blocks:** none

## Goal
Read `cursor.api.request.{input,output,cache_read,cache_creation}_tokens` per request and scope a capture by `cursor.conversation.id`, instead of throwing those fields away and summing a session-blind aggregate metric. All five keys are **Specification** (ledger §A5.2:152 for the join key, :166 for the four token attributes).

## Definition of done
1. Given an export containing two conversations, `capture --session <cursor.conversation.id>` returns tokens for **only** that conversation, and the scoped totals differ from the unscoped ones. This is supplied: `cursor.api.request` is a **log** event, and `cursor.conversation.id` is a documented log join key (ledger §A5.2:152).
2. **The aggregate fallback is unscopable, and the DoD says what that costs (V3-#8).** `cursor.token.usage` is a metric whose only attributes are `cursor.token.type`, `cursor.model.name` (opt), `cursor.api.status` (opt) and `cursor.api.billable` (opt) — **there is no conversation id on it** (ledger §A5.2:158). So the fallback is **export-scoped, never session-scoped**, and the two cases split:
   - **no `--session`** → the aggregate candidate is eligible and, absent a per-request candidate, wins: `Source: "otel_aggregate"`, and the spec doc records that the number covers the whole export;
   - **`--session <id>` given, no per-request events** → the aggregate candidate is **ineligible** (SC item 8's session-eligibility rule) and `tokens` is `unknown` with the reason *"cursor.token.usage carries no conversation id; cannot scope to session `<id>`"*. **Not** a silently unscoped sum wearing a session's name, which is the R-SA-02 failure this epic exists to prevent.
   `cursor.model.name` is the only further scoping the metric permits, and this slice does not use it.
3. **The new `cursor.*` literals live in `profiler/cursor_wirekeys.go`** (D5). This slice therefore **owns that file jointly with S0**, which creates it in wave 2. Round 2 caught that S6's DoD requires new wire keys while its Files omitted the only file allowed to hold them, which made the slice unbuildable as scoped under S8a's guardrail 4.
4. **Two candidates, two labels, and the label matches the metric that produced it (V4-#1, C4-#2, D12).** This slice assigns `Profile.Tokens` nowhere; it appends to SC's candidate list and calls `SelectTokenSource`:
   - per-request `cursor.api.request.*_tokens` → `TokenCandidate{Source: "otel", SessionScoped: true}`;
   - the `cursor.token.usage` fallback → `TokenCandidate{Source: "otel_aggregate", SessionScoped: false}` — **the same label S0 registers for the same metric**, because it is the same export-wide number read by the same rule. Round 3's DoD 2 said the fallback labels the result `otel_aggregate` while its DoD 4 said the slice "registers an `otel` candidate", so one slice named one number two ways and neither label was ranked (C4-#2).
   SC's total order ranks `otel` above `otel_aggregate` above `mcp_reported` above `estimated`, so the mixed case resolves without this slice deciding anything: **per-request wins, the aggregate is discarded rather than added to it, and nothing double-counts.**
5. **Degrades, never fails hard (R-SA-13).** An export with no `cursor.api.request` events and no `cursor.token.usage` metric registers no candidate at all; `tokens` is `unknown` with SC's empty-list reason, every other metric is unaffected, and the command exits 0. The register assigned R-SA-13 to this slice; round 3's `## Requirements` did not carry it (V4-#14).

## Test approach
`profiler/cursor_scope_test.go` (new, this slice's own file): a two-conversation export fixture asserting scoped totals; an aggregate-only fixture **without** `--session` asserting both the summed value **and** the `otel_aggregate` label; an aggregate-only fixture **with** `--session` asserting `unknown` and the exact reason string (DoD 2's second case — the assertion round 2 had no way to make); a mixed fixture (some requests scoped, some not) asserting the adapter prefers per-request and does not double-count, with the discarded aggregate contributing **no** field to `TokenCounts`; an assertion that an unknown `--session` yields `unknown`-with-reason, never a silent zero (R-SA-02); an empty-export fixture asserting DoD 5; and an AST/grep assertion that this file assigns `Profile.Tokens` nowhere (guardrail 5's property, asserted locally). Fixtures spell `cursor.*` keys directly — the second place D5 allows is `*_test.go`.
