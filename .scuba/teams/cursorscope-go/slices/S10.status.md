## Goal
`skill-scope export --spool <f>` POSTs OTLP/HTTP JSON traces + metrics to a configured endpoint — hand-rolled with `encoding/json` + `net/http`, zero dependencies.

**S2 added as a dependency at the spec gate:** this slice extends `profiler/cmd/skill-scope/`, which **S2 creates**. Declaring only S1 hid a transitive block behind a slice gated on User Question 1.

## Definition of done
1. A fake collector receives correctly nested spans — conversation → generation → tool — built from **SC's `Profile.SessionID`, `ToolCallEntry.GenerationID` and `.ID`/`.ParentID`**. The nesting is representable only because SC adds those fields; without them "correctly nested spans" was an assertion with no carrier.
2. Our own skill attributes are namespaced `skill_architect.skill.*` (**Design decision**, ledger §A6:214 states it as a recommendation; nothing specifies it), and **no `cursor.*` string appears anywhere in the exporter** (**D4**): R-CS-16's "reuse cursorscope's `cursor_*_total` metric names" is **dropped**, because emitting `cursor_*` from a tool that is not Cursor is precisely the invented-telemetry failure R-SA-14 forbids. **This is S10's half of R-SA-14** — the register now lists S10 alongside S0 and S8a, which round 1 omitted while this file claimed the requirement. It also removes any collision with S8a's guardrail 4.
3. `profiler/go.mod` still declares **zero** requires.
4. No `chars/4` estimate appears in any `gen_ai.usage.*_tokens` field. The `gen_ai.usage.*` names themselves are **Specification** (ledger §A6:210); that semconv defines **no** skill or rule convention is also Specification (§A6:212).
