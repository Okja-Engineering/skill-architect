## Goal
Port `classifyInvocation` / `skillNameFromPath` into Go and emit the first activation entry in this repo that actually **names a skill** — from a free, local, non-Enterprise surface.

**Framing corrected at the spec gate.** The old claim, "the first non-`unknown` activation any adapter has ever emitted", is false: `extractCursorSkillActivation` (`cursor.go:259-273`) already returns `present` today whenever an export contains `cursor.skill.activated` — it just reads the wrong keys (`skill_name` instead of `cursor.skill.name`), so it emits `present` with an **empty** skill name, and `profiler_test.go:644-652` passes on a fixture built from those wrong keys. The honest claim: *the first activation that names a real skill, and the first from a non-Enterprise surface.* S0 fixes the Enterprise path; this slice creates the local one.

## Definition of done
1. `classifyInvocation` returns `mcp | cli | skill | subagent | tool` with a name and detail across cursorscope's transcribed table.
2. A `Profile` built from **SP1's real fixture** reports `skill_activation: present` with a **non-empty** `SkillName`, `Source: "hooks"`, and `Trigger: "inferred_file_read"`.
3. `attribution: present`, mapping at least one `tool_use_id` to that skill (R-SA-07 — the epic's primary success condition).
4. The `Trigger` value comes from the **hook-inferred** vocabulary only — `inferred_file_read | inferred_shell_command | inferred_subagent` (**D6**), which is disjoint from Cursor's first-party enum `agent_read | manually_attached | skill_name_in_prompt`. The old DoD said "explicitly marked as *inferred*" and named no vocabulary, which collided with S0's pass-through of the real enum. SC defines both sets; this slice may emit only the `inferred_*` one.

## Test approach
`profiler/attribution_test.go` (new, this slice's own file):
- table-driven cases transcribed from cursorscope's `attribution.test.js` and `gen-ai-semconv.test.js` as the behavioral oracle (**External evidence**; §G13 — those suites were listed, not executed, so transcription errors are a real risk: transcribe assertions, not implementations);
- one end-to-end assertion against SP1's committed fixture, which is what makes the DoD's "real skill name" checkable rather than aspirational;
- a negative test that no `inferred_*` value can be written where a first-party trigger belongs and vice versa (D6 is enforceable, not just documented).
