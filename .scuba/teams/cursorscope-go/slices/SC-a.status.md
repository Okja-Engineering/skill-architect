## Goal
One slice owns `profiler/types.go`, `profiler/tokens_select.go`, `profiler/validate.go` and `docs/profiler-spec.md`, and gives the contract the *vocabulary and the pure functions* the rest of the epic asserts against. It reads no hook, parses no export and edits **no line of `compare.go`** — that is `SC-b`.

**Created at round 5 by splitting `SC` on the seam §H2 named** (V5-#15; both round-5 hunters recommended it). Round 4's SC was 19 DoD items across seven files — the epic's largest PR, and the one every other slice waits on. The seam is real, not cosmetic: **ten** slices need only this half (S0 also needs SC-b, see its file), and this half contains nothing that touches the comparison wire format. History: created by spec-gate root **R1**; widened at round 2 (representability sweep); corrected at round 3 (source-supply sweep); corrected at round 4 (enforcement sweep, V4-#4/#5/#6/#8, C4-#3, and V4-#1 which moved the token selector here from S5); corrected at round 5 (V5-#2/#3/#4/#5 — the selector's admissible-source set, its assignment site, the eligibility rule's width, and the validator's `Status` rule).

## Definition of done
1. `ActivationEntry` gains `Source string` — carries `cursor.skill.source`, whose six values `unspecified|workspace|user|builtin|plugin|claude` are **Specification** (ledger §A5.2:169, Cursor OTel Wire Reference). R-RL-05.
2. `ToolCallEntry` gains `Status string`, a **verbatim pass-through of `cursor.tool.status`, whose vocabulary is `success | failure | aborted`** (ledger §A5.2:159). *There is no `error` value, and no fourth value is added for hooks* — S1b derives all three from `postToolUse`/`postToolUseFailure` (D11) rather than widening the vocabulary. **`""` is a fourth *legal* state and not a fourth value: it is the pre-v1.1 encoding, which item 14 (SC-b) declares legitimate and gates on rather than rejecting.** `Count int` is added for counter-derived rows. `Success bool` stays and equals `Status == "success"` when `Status` is set.
3. `ToolCallEntry` gains the identity/hierarchy fields **`ID string`**, **`GenerationID string`**, **`ParentID string`**. **`ID` and `ParentID` hold one identifier kind — a tool-call id — and only that.** The wire spelling differs by event and the spec doc states the mapping: `tool_use_id` on `preToolUse`/`postToolUse`/`postToolUseFailure` (ledger §A5.1:120,121,122), **`tool_call_id` on `subagentStart`** (§A5.1:131), which is the parent tool call of a subagent branch and therefore feeds `ParentID`. **`parent_conversation_id` is a conversation id and is barred from `ParentID`** — mixing kinds in one field is what made "chains" untestable. `Profile.SessionID` carries `conversation_id`; the chain is `SessionID` → `GenerationID` → `ID`, with `ParentID` for branches.
4. **`Attribution.Target` is *not* narrowed.** The shipped contract permits two kinds: `types.go:114` documents `Attribution` as linking "a target (tool call ID **or output**) to a skill", and `profiler-spec.md:154` spells the second kind out as "tool call ID **or output identifier**" (C4-#8). v1.1 keeps both, because `beforeReadFile` — S3's inferring event — carries **no `tool_use_id`** (ledger §A5.1:127) and could never satisfy a tool-call-only rule. The referential rule is therefore a disjunction, and it is what makes it checkable: **every `Target` either (a) resolves to some `ToolCallEntry.ID` in the same profile, or (b) is an output identifier bearing a declared scheme prefix — `file://<workspace-relative path>` is the only scheme v1.1 declares.** A bare, schemeless, unresolvable string is a contract violation — enforced by item 12, not by prose. Which form S3 emits is D11's attribution join, decided by SP1.
5. **Context-window occupancy gets its own carrier; `TokenCounts` does not grow (V3-#2, D12).** Round 2 put `ContextTokens` / `ContextWindowSize` / `ContextUsagePercent` into `TokenCounts`, which forced one `TokenResult.Source` (`types.go:23`; spec:36 "`Source` is always populated when `State == present`") to label two different quantities from two different suppliers. Context occupancy at compaction is not token *flow*. So: a new `MetricName` **`context_window`**, a new `ContextData{ContextTokens, ContextWindowSize, ContextUsagePercent}` and `ContextResult`, and a new **pointer** field `ContextWindow *ContextResult json:"context_window,omitempty"` declared **last** on `Profile` — a pointer, because a value-typed struct ignores `omitempty` and would break item 17. `TokenCounts` is left exactly as shipped. R-CS-13/R-RL-18 are representable, and each result keeps one honest source. **Its comparator is SC-b's** (SC-b item 10), including the nil case this pointer makes possible.
6. `MetricSource` gains `estimated`, `otel_aggregate`, `mcp_reported` — nine constants in total.
7. `CapabilityReport` gains `Notes map[MetricName]string` (**why** a metric is `none` — today `Capabilities` is `map[MetricName]MetricSource`, `types.go:50-55`, with no reason channel) and `Available map[MetricName][]MetricSource` (a metric may have two sources; today the second assignment silently overwrites the first, `types.go:54`).

8. **The token single-writer carrier — `Profile.Tokens` has exactly one assigning function, and it lives here (V4-#1, V5-#3, D12).** `profiler/tokens_select.go` (new, this slice) defines:
   - `type TokenCandidate struct { Source MetricSource; Counts TokenCounts; SessionScoped bool; SingleConversation bool; Caveat string }`;
   - `type TokenCandidates struct { … }` with `func (c *TokenCandidates) Add(TokenCandidate)` and `func (c *TokenCandidates) List() []TokenCandidate` — **the accumulator, owned here.** Round 4 named a selector and a rank but no accumulator, so "every producing slice appends a candidate" named no thing to append to (V5-#3). One `*TokenCandidates` is threaded through a Cursor capture; producers only `Add`.
   - `func SelectTokenSource(cands []TokenCandidate, sessionRequested bool) TokenResult` — the pure ranking function, exported so its ladder can be proven pairwise;
   - **`func ApplyTokenSelection(p *Profile, cands []TokenCandidate, sessionRequested bool)` — the only function in the epic that contains the text `p.Tokens = …`.** It is one line over `SelectTokenSource`. Round 4's defect was that `SelectTokenSource` had no `*Profile` parameter, so *someone* had to write the assignment and the only allowlisted file structurally could not (V5-#3). It can now, and does.
   - **Who calls it, by name — two call sites in wave 2/3, one per capture branch, collapsed to one by S7:** the OTel/export branch calls it once in `profiler/cursor.go`, **created by S0**, after every export-derived candidate has been `Add`ed (S6 and its Enterprise per-request path `Add` into that same accumulator and add no second call site); the hook-spool branch calls it once as the **last statement of `enrich()`** in `profiler/enrich.go`, **created by S1b**, after `enrichAttribution` and `enrichTokens` have run — which is what lets **S5** (`tokens.go`) and **S9** (`cursor_admin_api.go`) register candidates from inside the enrichment seam without an assignment or a call site of their own. **S7 unifies the two branches and asserts exactly one call site remains.**
   - **The rank is total over all five flow labels:** `server_api` > `otel` > **`otel_aggregate`** > `mcp_reported` > `estimated`. It follows D3's honesty-class order (`measured_billed` > `harness_reported` > `self_reported` > `estimated`); the one intra-class tie — `otel` vs `otel_aggregate`, both `harness_reported` — breaks on **scope precision**, because `cursor.api.request` is per-request and conversation-scoped while `cursor.token.usage` is an export-wide sum (ledger §A5.2:152 vs :158). Both are the harness reporting on itself, so both outrank an MCP server's self-report.
   - **The admissible-source set is an allowlist, not a denylist (V5-#2).** `SelectTokenSource` accepts a candidate **only** if its `Source` is one of those five flow labels; **every other value — `hooks`, `session_data`, `sqlite`, `none`, `""` and any unrecognized string — is refused by name, with the string in the reason.** Stated as an allowlist because that is the set S8a's guardrail 5(b) is scoped to and the set the spec doc publishes: **the guardrail's width, this admissible set, and the files this epic owns are one set.** D12's justification is why `hooks` is the member that matters on the Cursor path: no hook event reports input/output/cache flow for a model call (ledger Q1:300). `hooks` appears on `context_window`, `tool_calls` and `timing`; never on `tokens`.
   - **Session eligibility, so an unscoped number can never wear a session's name — and it is a rule about unscopable aggregates, not a rule about tokens (V5-#4).** This slice exports the predicate **once** and both metrics use it:
     - `func SessionEligible(sessionRequested, sourceIsSessionScoped, exportIsSingleConversation bool) bool` — true iff `!sessionRequested || sourceIsSessionScoped || exportIsSingleConversation`;
     - `func UnscopedAggregateReason(wireKey, session string) string` — the single reason text, so no slice writes its own prose: *"`<wireKey>` carries no conversation id; cannot scope to session `<session>`"*.
     `SelectTokenSource` drops an ineligible candidate and names it in the reason. **The same predicate binds `tool_calls`:** `cursor.tool.calls` is a delta counter with no `cursor.conversation.id` (ledger §A5.2:159), so under `--session` it is ineligible on exactly the same terms — S0 DoD 4 is written to this function rather than to a local promise. The **single-conversation escape** is the third argument: an export-wide aggregate *is* provably one conversation's number when the export contains exactly that one conversation. **How that is detected is stated where the export is read (S0 DoD 3a), not invented here:** the set of distinct `cursor.conversation.id` values over the export's **log** records (`cursor.api.request`, ledger §A5.2:152 — the conversation id is a log attribute and appears on neither metric) is exactly `{<requested session>}`. An export with no log records leaves that set empty, so single-conversation is **not** established and the metric is `unknown`. A metric admitted through the escape carries `CaveatExportScopedAggregate` (item 9).
   - An empty or fully-ineligible candidate list yields `UnknownTokenResult` with a reason naming what was dropped and why — never a zero-valued `present` (R-SA-02).
   - A `present` result requires the winning candidate to supply both `Input` and `Output`; otherwise `unknown` with a reason naming the source and the missing field. **Lower-ranked candidates are discarded, not merged:** no field of `TokenCounts` is ever filled from a source other than the one named in `TokenResult.Source`.

9. **`RawMetricResult` gains `Caveat string json:"caveat,omitempty"` — the carrier D11's timing caveat has never had (C4-#3).** `Reason` is contractually empty when `State == present` (`profiler-spec.md:33`, retained by D2), and `CapabilityReport.Notes` describes a *capability*, not a captured value — so a `present` value with a stated caveat had nowhere to live and S1b's DoD claimed the profile stated one anyway. `Caveat` is permitted **only** when `State == present`, and its value must be one of this slice's declared constants — **a closed set, fail-closed exactly like the honesty classes**, so the field cannot become free prose:
   - `CaveatHookReceiptClock` — *"hook-receipt wall-clock, not model time; includes hook-process scheduling latency and excludes everything before the first hook fires"* (D11.1; set by S1b on `timing`, by S3 on activation timestamps);
   - `CaveatEstimatedFlow` — *"chars/4 estimate; structurally undercounts billed input and omits the system prompt, the always-loaded skill listing and the cache split"* (D12/R-CS-11; set by S5 on an `estimated` token result);
   - **`CaveatExportScopedAggregate`** — *"export-wide aggregate; admitted for this session only because the export contains exactly one conversation id and it is the requested one"* (V5-#4; set by S0 and by S6's fallback on `tokens` and on `tool_calls`, and only through item 8's single-conversation escape).
   Any other non-empty `Caveat` is a contract violation item 12 catches. The field is `omitempty` and declared last, so item 17 holds.

12. **The referential rule gets a validator, named here and wired by SC-b (V4-#5, C4-#3, V5-#5).** `profiler/validate.go` (new, this slice) defines **`func ValidateProfile(p Profile) []error`**, returning one error per contract violation:
    - (a) an `Attribution.Target` that neither resolves to a `ToolCallEntry.ID` nor bears a declared scheme prefix (item 4);
    - (b) a `present` result whose `Source` maps to class `none` or `unrecognized` (item 15) — **this is what covers `none`/`""`/typo'd labels at runtime, on every adapter, which is why S8a's source-level walk does not duplicate it**;
    - (c) a `ToolCallEntry.Status` that is **non-empty and** outside `success|failure|aborted`. **`""` is legal and passes.** Round 4 rejected it, contradicting item 14 (SC-b), which declares the `Status`-less encoding legitimate and *gates* on it: every pre-v1.1 row carries `Status: ""`, so the round-4 rule would have flooded `ComparisonReport.Notes` on every legacy comparison the moment SC-b wired the call (V5-#5). The validator rejects a *wrong* value, not an *absent* one — the same distinction R-SA-02 draws everywhere else in this epic;
    - (d) a `tokens` result labelled with anything outside item 8's five-label allowlist, naming the string;
    - (e) a `Caveat` outside the declared set, or set on a non-`present` result (item 9).
    **It is called, not decorative** — but the call site is `CompareProfiles`, which lives in `compare.go`, so **SC-b wires it** (SC-b item 12w) and this slice ships it with `TestValidateProfile` proving each rule directly. No existing fixture trips it: all four shipped adapters return `attribution: unconditional unknown`, so rule (a) has nothing to fire on until S3 ships, and rule (c) now passes every legacy row. S3, S5 and S1b assert against this function rather than restating the rule.

15. **Honesty classes are total and fail-closed (D3).** All nine `MetricSource` constants map to exactly one class, **including `SourceNone` (`types.go:46`) → class `none`**, **and so does the empty string**: the **five** `Unknown*Result` constructors — `UnknownTokenResult`, `UnknownToolCallResult`, `UnknownActivationResult`, `UnknownTimingResult`, `UnknownAttributionResult` (`types.go:196,216,231,246,261`) — leave `Source` at `""`, as does the **sixth `Source == ""` constructor, `ErrorTokenResult` (`types.go:201`)**, which round 3 counted among "six `Unknown*Result`" without naming it (C4-#4). So `""` is a zero value the class function really receives and it maps to `none`, not `unrecognized` — an absent provenance is not a typo'd one. A `present` result carrying `none` (from either spelling) is a contract violation. Because `RawMetricResult.Source` is a free `string`, any *other* unlisted value maps to **`unrecognized`**; SC-b's comparators refuse it, naming the string.
16. **The additive rule covers all four wire strings, not two (V4-#6) — stated here, proven half here and half in SC-b.** D1 covered `ProfileSchema`; D13 added `ComparisonSchema`; `ExperimentSchema` (`experiment.go:14`) and `ExperimentPlanSchema` (`experiment.go:17`) are two more strictly-validated wire strings (`experiment.go:98-99,237-238` reject any other value), and **S7 adds `HookSpool` inside both**. Neither slice edits a line of `experiment.go`: marshalling existing types into a golden needs no code change.
17. **Every field this slice and SC-b add carries `omitempty` and is declared after the existing fields of its struct** (`Profile.ContextWindow` is a pointer for the same reason). Round 4 scoped this to "items 1–9" and so omitted item 11's `BaselineSource`/`CandidateSource` on `MetricComparison`, which are two more fields on a shipped wire type (V5-#11). The rule is stated once, here, and binds **every** field either half of the contract slice adds — items 1–9 and 11 alike. This is what makes item 16 true rather than contradictory.

## Test approach
`profiler/contract_test.go` (new, this slice's own file; SC-b appends its own `compare_contract_test.go` rather than editing this one):
- **Golden provenance is pinned, or byte-identity proves nothing (V3-#15).** `profile-v1-pre11.json` is generated **once**, by marshalling a fully-populated value through the *merge-base* source (`git show <merge-base-sha>:profiler/types.go`), and committed **verbatim** — never hand-indented, never reordered. The producing command and the SHA go in a header comment in this test file. It then unmarshals and re-marshals **byte-identically** (`Marshal(Unmarshal(golden)) == golden`) → proves additivity and item 17's `omitempty` discipline for every field added to `types.go`;
- a table asserting all **nine** `MetricSource` constants map to exactly one honesty class, that `SourceNone` **and `""`** map to `none`, that adding a constant without a class fails the test, and that the wire string `"wat"` maps to `unrecognized`;
- **`SelectTokenSource` and `ApplyTokenSelection` (item 8), the heart of the single-writer rule:** the full rank ladder asserted pairwise — `server_api` beats `otel` beats `otel_aggregate` beats `mcp_reported` beats `estimated`, with **every** `TokenCounts` field of the winner's and **no** field retained from a discarded candidate; the allowlist proven as an allowlist — `hooks`, `session_data`, `sqlite`, `none`, `""` **and** an invented `"wat"` each refused with the string in the reason; an empty list yielding `unknown`; an `Input`-only winner yielding `unknown` naming the missing field; `TokenCandidates.Add` accumulating in registration order and `ApplyTokenSelection` writing `p.Tokens` and nothing else on `p`;
- **`SessionEligible` as one rule for two metrics (item 8, V5-#4):** a truth table over `(sessionRequested, sourceIsSessionScoped, exportIsSingleConversation)` — including the escape row `(true, false, true) → eligible` and the row that matters most, `(true, false, false) → ineligible`; an `otel_aggregate` candidate with `SessionScoped:false, SingleConversation:false` ineligible under `sessionRequested:true`, yielding `unknown` with `UnscopedAggregateReason("cursor.token.usage", "<id>")` verbatim; the same candidate with `SingleConversation:true` **admitted** and carrying `CaveatExportScopedAggregate`;
- **`TestValidateProfile` (item 12):** a profile whose `Target` is a `ToolCallEntry.ID` passes; one whose `Target` is `file://skills/audit/SKILL.md` passes; one whose `Target` is a bare unresolvable string **fails**; a `present` result with `Source: ""` fails; a `Status` of `"error"` **fails**; **a `Status` of `""` passes, and a whole pre-v1.1 profile of `Status`-less rows returns zero errors** (V5-#5 — the assertion that pins the legacy encoding as legal); a `tokens` result labelled `hooks` fails and one labelled `"wat"` fails; an undeclared `Caveat` string fails, and a declared one on a non-`present` result fails;
- a `Probe()`-shaped table asserting `Notes` and `Available` round-trip through JSON, and a `context_window` round-trip asserting the field is **absent** from the JSON when nil.

All **34 existing Go tests stay green** — no field is removed, no default changes, and this slice adds no call into any existing code path.
