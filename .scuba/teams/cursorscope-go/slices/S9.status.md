## Goal
Join hook `conversation_id` to `POST /teams/filtered-usage-events` → `conversationId` and get genuinely billed per-request tokens — the cheapest real-token path for Cursor that does **not** require Enterprise OTel.

## Definition of done
1. With a Team admin key, a hook-sourced profile's `tokens` become `present` with `Source: "server_api"` and the four-way splits mapped onto `TokenCounts` explicitly — `inputTokens→Input`, `outputTokens→Output`, `cacheReadTokens→CacheRead`, **`cacheWriteTokens→CacheCreation`** (the wire field is named "write", the contract field "creation"; the mapping is stated so it cannot drift). Field names are **Specification**, ledger §A5.3:180. The join key is supplied on both sides: `filtered-usage-events.conversationId` (§A5.3:180, optional on the wire) and the hooks' base `conversation_id` (§A5.1:113).
2. Without a key, the metric is `unknown` with an actionable reason and **nothing else in the profile changes** (R-SA-13).
3. **This slice does not assign `Profile.Tokens` (D12, V3-#2, V4-#1).** It appends `TokenCandidate{Source: "server_api", SessionScoped: true}` to SC's candidate list and calls **`SelectTokenSource`** (SC item 8), which ranks it above every other label. Round 2 had this slice writing `tokens` directly while S5 also did, so whichever ran last silently overwrote the other's label — the failure D12 exists to prevent. Every field of `TokenCounts` in a `server_api` result comes from the Admin API response; no field is retained from a discarded `estimated`, `mcp_reported`, `otel` or `otel_aggregate` candidate.
4. A response row whose `conversationId` is absent (it is an **optional** field, §A5.3:180) contributes nothing and is not silently attributed to the profile's session.
