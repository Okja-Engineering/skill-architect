## Guardrail rules (grep + go vet + Go tests — not semgrep)
1. A `python3` invocation in any shell script (`AGENTS.md:6`).
2. A `MetricResult` built as `present` with a `Source` **other than** `estimated`, inside or returned from a function whose name contains `estimate`. **Rewritten at the spec gate:** the old rule forbade `present` outright from an `estimate*` function, which forbade exactly what Fork (vi) option 2 mandates — a direct design conflict. The rule forbids the **mislabel**, not the state.
3. An unredacted prompt or payload written to disk (R-CS-18/19).
4. A `cursor.` literal outside `profiler/cursor_wirekeys.go` and `*_test.go` files (**D5**). The old rule said "the one file allowed to declare them" without naming it, and collided with S10's DoD; per **D4** S10 emits no `cursor.*` string at all, so the conflict is gone.

## Test approach
`tests/test_guardrails.sh` (new): for each of rules 1, 3 and 4, seed a violation in a scratch copy of the tree, assert CI's check exits non-zero, remove it, assert it exits zero — red→green per rule, so the guardrail is proven to actually catch something rather than merely existing. Rule 2 is a Go test over the package's declarations (`go vet`-adjacent, using the same source scan) with the same seeded-violation pattern. Docs are reviewed for a label on every claim; the label vocabulary is `AGENTS.md:18-23`.
