## Goal
Redaction runs before the spool write, not before export. Prompts hitting local disk is more sensitive than cursorscope's in-memory → OTLP path, so this is non-negotiable.

## Definition of done
1. Given a payload containing an email, a bearer token, an `sk-` key and a **16 KB** prompt, the spool file on disk contains none of the four secrets and records prompt **length** only — the `[redacted string len=N]` shape cursorscope uses (**External evidence**, `src/privacy.js:24`).
2. **Truncation, with the constant re-derived from its real home (C3-#5).** The 8192 limit is `TOOL_PAYLOAD_MAX_LEN` in cursorscope's **`src/gen-ai-semconv.js:34`** — *not* `src/privacy.js*, which round 2 cited and which contains no truncation at all — and it is **env-overridable** there (`CURSOR_TOOL_PAYLOAD_MAX_LEN`). Its behaviour at `:223,226` is `serialized.slice(0, 8192)` **plus a `…` marker**, i.e. a JS *character* slice yielding 8192 chars **and then** a 3-byte marker appended — so "truncated to exactly 8192 bytes with a marker" was wrong twice over. **This slice's rule, stated in its own terms:** a payload longer than 8192 **bytes** is truncated to at most 8192 bytes **including** a 1-byte `\x1a`-free ASCII marker suffix (`"…"` is 3 bytes in UTF-8; use `"[+]"` or reserve the bytes) and is never split mid-rune; a **4 KB** payload is written untruncated. The boundary is proven from **both** sides, and the constant is ours, taken as a default from cursorscope, not inherited as a contract.
3. Redaction sits on the write path in `profiler/hooks.go`, so it holds for the stdin binary and for any future sink (S11) without being re-implemented — and **the redactor is the only path to the spool writer**. Concretely, against the two names S1a pins: `WriteHookEvent` redacts then calls the package-private `appendSpoolLine`, and nothing outside `profiler/hooks.go` / `profiler/privacy.go` calls the latter. That is exactly the property S8a's guardrail 3 greps for.

**Fixed at the spec gate:** the old DoD used a 4 KB prompt to prove truncation at 8192 — a payload under the limit cannot demonstrate the limit. The boundary is now proven from **both** sides: one payload over it, one under it.

## Test approach
`profiler/privacy_test.go` (new, this slice's own file): table cases transcribed from cursorscope's `privacy.test.js` (**External evidence**; §G13 — listed, not executed, so transcribe the assertions and re-derive the implementation). **Note that `privacy.test.js` has no truncation case** — its six cases cover email masking, bearer/`sk-` redaction, sensitive object keys, string-body hiding and nested recursion — so the truncation assertions below are **ours**, derived from `gen-ai-semconv.js:223,226`, and must not be described in the PR as transcribed from an oracle that does not test it. Plus:
- a `grep` absence assertion against the **written spool file** for each of the four secrets — absence checks use `grep`, per `AGENTS.md:12` ("Semgrep is for pattern finding, not absence detection");
- an exact byte-length assertion at the 8192 cap for the over-limit payload, an assertion that the marker is present and the result is valid UTF-8 (no split rune), and an exact round-trip assertion for the 4 KB one;
- a test that a payload with **no** secrets passes through unmodified, so redaction cannot quietly corrupt clean data.
