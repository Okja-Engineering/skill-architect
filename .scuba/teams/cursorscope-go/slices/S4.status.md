## Goal
Redaction runs before the spool write, not before export. Prompts hitting local disk is more sensitive than cursorscope's in-memory → OTLP path, so this is non-negotiable.

## Definition of done
Given a payload containing an email, a bearer token, an `sk-` key and a **16 KB** prompt, the spool file on disk contains none of the four secrets and records prompt **length** only; the 16 KB payload is truncated to exactly **8192** bytes with a truncation marker, while a **4 KB** payload is written untruncated. Redaction sits on the write path, so it holds for the stdin binary and for any future sink (S11) without being re-implemented.

**Fixed at the spec gate:** the old DoD used a 4 KB prompt to prove truncation at 8192 — a payload under the limit cannot demonstrate the limit. The boundary is now proven from **both** sides: one payload over it, one under it.

## Test approach
`profiler/privacy_test.go` (new, this slice's own file): table cases transcribed from cursorscope's `privacy.test.js` (**External evidence**; §G13 — listed, not executed, so transcribe the assertions and re-derive the implementation). Plus:
- a `grep` absence assertion against the **written spool file** for each of the four secrets — absence checks use `grep`, per `AGENTS.md:12` ("Semgrep is for pattern finding, not absence detection");
- an exact byte-length assertion at 8192 for the over-limit payload and an exact round-trip assertion for the 4 KB one;
- a test that a payload with **no** secrets passes through unmodified, so redaction cannot quietly corrupt clean data.
