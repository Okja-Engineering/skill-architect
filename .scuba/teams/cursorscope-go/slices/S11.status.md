## Goal
A long-running `skill-scope serve` accepts `POST /cursor/hooks` as an optional second sink onto the same spool the stdin path writes.

**S2 added as a dependency at the spec gate:** `serve.go` lives in `profiler/cmd/skill-scope/`, which **S2 creates**.

## Definition of done
POSTing SP1's captured fixtures through the server produces a spool **byte-equivalent** to the stdin path's output for the same input; a backdated entry is closed and marked stale by the TTL sweep rather than leaked.

## Test approach
An integration test: start the server on an ephemeral port, POST the fixtures, run the same fixtures through the stdin binary, `diff` the two spools — byte-equivalence is the whole claim, so it is the whole assertion. A TTL test with backdated timestamps injected through cursorscope's `_testHooks` pattern, asserting the entry is closed rather than retained. A malformed-body test asserting the server responds 4xx and writes nothing, so a bad POST cannot corrupt a spool the stdin path is also appending to.

## Requirements
R-CS-22, R-CS-04 (**the original HTTP-ingest form only** — the adapted spool form is already satisfied by S1a, D9)
**Not claimed:** R-CS-06 (the roadmap assigns its adapted reader-side form to S1b; the original in-process TTL form was deleted by Fork (i) and is not resurrected as a requirement) · R-CS-23 (assigned to S2 as `doctor`).

## Next
**Lowest priority in the epic; recommend it never ships.** Fork (i)'s default deletes this requirement rather than porting it. The daemon is the sole reason cursorscope needs a pidfile, auto-start bash (~104 lines in `ensure-cursorscope.sh`), version-mismatch restart, and a TTL sweep — and it shipped a memory-leak fix in 0.3.7 for exactly the long-lived state this reintroduces.

It only becomes worth building if the user needs real-time steering or multi-machine fan-in. The design is deliberately reversible: the daemon consumes the same spool the stdin path writes, so nothing upstream changes if it lands later.
