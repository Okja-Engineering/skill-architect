## Goal
A long-running `skill-scope serve` accepts `POST /cursor/hooks` as an optional second sink onto the same spool the stdin path writes.

**S2 added as a dependency at the spec gate:** `serve.go` lives in `profiler/cmd/skill-scope/`, which **S2 creates**.

## Definition of done
1. POSTing **S1a's 21 hook fixtures** through the server produces a spool **byte-equivalent** to what the stdin binary produces for the same input.
2. A malformed body returns 4xx and writes nothing, so a bad POST cannot corrupt a spool the stdin path is also appending to.
3. **The server holds no per-session state.** It is a sink, not a state machine: each request is redacted (S4's path, inherited through S1a's writer) and appended, then forgotten. That is precisely *why* byte-equivalence with the stdin path is achievable, and it is why **no TTL sweep appears in this slice**.

**Two round-2 corrections.**
- *Fixtures.* Round 1's DoD required **SP1's** fixtures while the dependency list declared only S1a and S2 — an assertion depending on a slice that was not a dependency. Byte-equivalence is a property of the two write paths, not of a fixture's provenance, so the DoD now binds to **S1a's 21 fixtures**, which this slice already depends on. If SP1's real capture exists, use it as an additional case: that is an upgrade, not a dependency, and it keeps this conditional slice off the critical path of a gate it does not need.
- *TTL.* Round 1's DoD built a TTL sweep while the Requirements section disclaimed R-CS-06 — a slice implementing a requirement it says it does not claim. Resolved by deleting the sweep: with no per-session state there is nothing to expire. R-CS-06's adapted, reader-side form stays with **S1b**, and the original in-process form stays deleted by Fork (i).

## Test approach
`profiler/cmd/skill-scope/serve_test.go` (new, this slice's own file — round 1 named no test file, in violation of the roadmap's "every slice names its test"): start the server on an ephemeral port, POST the 21 fixtures, run the same fixtures through the stdin binary, `diff` the two spools — byte-equivalence is the whole claim, so it is the whole assertion. Plus a malformed-body test asserting 4xx and a zero-byte spool delta, and a concurrent test writing through both paths at once, asserting no interleaved line.

## Next
**Lowest priority in the epic; recommend it never ships.** Fork (i)'s default deletes this requirement rather than porting it. The daemon is the sole reason cursorscope needs a pidfile, auto-start bash (~104 lines in `ensure-cursorscope.sh`), version-mismatch restart, and a TTL sweep — and it shipped a memory-leak fix in 0.3.7 for exactly the long-lived state this reintroduces.

It only becomes worth building if the user needs real-time steering or multi-machine fan-in. The design is deliberately reversible: the daemon consumes the same spool the stdin path writes, so nothing upstream changes if it lands later.
