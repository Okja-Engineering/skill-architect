# S0 — Fix the Cursor OTel adapter against the wire reference

- **Stage:** ready once SC-a and SC-b merge
- **Owner:** unassigned
- **Branch:** none (target: `epic/skill-scope`)
- **Depends on:** **SC-a** (needs `ActivationEntry.Source`, `ToolCallEntry.Status`/`Count`, `MetricSource.otel_aggregate`, `CapabilityReport.Notes`, `TokenCandidates`/`ApplyTokenSelection`, `SessionEligible`, `CaveatExportScopedAggregate` — none of which exist today), **SC-b** (this slice is the one that starts emitting `Count`-bearing rows, and on `main` `countToolCalls` is `len(calls)` — see § Next)
- **Blocks:** S6, S7, **S8a** (guardrail 4 cannot go green until `cursor_wirekeys.go` exists — `cursor.go` holds **12** live `cursor.` literals at `:175,182,184,186,197,216,224,234,242,250,262,271`; guardrail 5(a) cannot go green until this slice replaces `cursor.go`'s **6** `.Tokens =` assignments at `:95,114,124,134,141,150`)

## Goal
Stop the shipped Cursor adapter lying. Correct every OTel attribute key to its Wire-Reference form, move `tool_calls` off `cursor.hook.execution_complete` onto the `cursor.tool.calls` metric, retract the false SQLite token capability, and collect every `cursor.*` literal into one file.

## Definition of done
Rewritten at the spec gate against the **actual wire shape** (root C); every enum below is cited to its source line, not transcribed by topic:
1. **All 12** live `cursor.*` literals live in `profiler/cursor_wirekeys.go` — one of the two places D5 allows (the other is `*_test.go`). **Eight are event/metric names; four are inside `Unknown*Result` reason strings** (`cursor.go:216,234,250,271` — "no cursor.token.usage metric found in OTel export" and its three siblings). Round 2 counted only the eight and would have left guardrail 4 red after this slice merged. The reason strings are therefore **composed** from the same constants (`fmt.Sprintf("no %s metric found in OTel export", wireTokenUsageMetric)`), not spelled out — which is also what keeps a renamed key from drifting out of its own error message. Verification is guardrail 4's own command, run in this PR: `grep -rn 'cursor\.' profiler/ --include='*.go'` minus `cursor_wirekeys.go` and `*_test.go` returns **zero** lines.
2. A Wire-Reference fixture yields `skill_activation: present` with a **non-empty** `ActivationEntry.SkillName` (from `cursor.skill.name`), `ActivationEntry.Source` (from `cursor.skill.source`: `unspecified|workspace|user|builtin|plugin|claude`), and a `Trigger` drawn only from the **first-party** enum `agent_read|manually_attached|skill_name_in_prompt` (D6). Both enums: **Specification**, ledger §A5.2:169.

3. **The export's conversation set is computed once, here, and both aggregate metrics use it (V5-#4).** The adapter derives `exportConversations` — the set of distinct `cursor.conversation.id` values over the export's **log** records (`cursor.api.request`; ledger §A5.2:152 states the conversation id is a *log* join key, and it appears on neither `cursor.token.usage` nor `cursor.tool.calls`). `singleConversation(session)` is then `len(exportConversations) == 1 && exportConversations[0] == session`. **An export with no log records leaves the set empty and single-conversation is NOT established** — an empty set is not a proof of scope, and treating it as one is precisely the R-SA-02 failure this epic exists to prevent. This one boolean is what SC-a item 8's `SessionEligible` takes as its third argument, and it serves `tokens` (DoD 3a) and `tool_calls` (DoD 4) identically. It is computed from the export the adapter already parses; it adds no new read.

3a. **`tokens` is registered as a candidate, labelled `otel_aggregate`, and this slice does not assign `Profile.Tokens` (V4-#1, V5-#3, D12).** The adapter reads the **`cursor.token.usage` metric**, whose `cursor.token.type` values are `input|output|cache_read|cache_creation` (**Specification**, ledger §A5.2:158) and whose attribute set carries **no conversation id** (§A5.2:158) — it is the same export-wide aggregate S6's fallback reads. Round 3 labelled it `otel` and assigned `Profile.Tokens` directly, which made this slice the **fourth** writer of a field D12 says has one, and gave the same metric two different labels depending on which slice read it. So:
   - this slice `Add`s `TokenCandidate{Source: otel_aggregate, SessionScoped: false, SingleConversation: singleConversation(session)}` to the capture's `*TokenCandidates`;
   - **this slice creates the OTel branch's single call site**: one `ApplyTokenSelection(profile, cands.List(), sessionRequested)` in `profiler/cursor.go`, placed after every export-derived candidate has been `Add`ed. That call is the *only* line in this file that leads to `Profile.Tokens` being written, and the write itself lives in SC-a's `tokens_select.go` (V5-#3 — round 4 named a selector with no `*Profile` parameter, so the assignment had no owned home and all five producers disclaimed it). **S6 `Add`s into this same accumulator and adds no second call site.**
   - Consequences that fall out of SC-a's rules rather than being restated here: with `--session` over a multi-conversation or log-less export the candidate is ineligible and `tokens` is `unknown` with `UnscopedAggregateReason("cursor.token.usage", session)`; with `--session` over a **single-conversation** export it is admitted and carries `CaveatExportScopedAggregate`; when S6 later registers a per-request `otel` candidate, `otel` outranks it and nothing silently overwrites anything.
   The dead `reasoning`/`reasoning_output` cases are **deleted** — the enum has no such member.

4. **`tool_calls` reads the `cursor.tool.calls` metric, and it is bound by the same session-eligibility rule as `tokens` (V5-#4).** That metric is **Specification**, ledger §A5.2:159, and it is a **delta counter**: no timestamp, no `cursor.conversation.id` (a *log* join key, §A5.2:152), and `cursor.tool.status` is **`success | failure | aborted`** — three values, verbatim; there is no `error`. Two consequences, and round 4 stated only the first:
   - **Shape:** one row per (`cursor.tool.name`, `cursor.tool.status`) group with `Count` set, `Status` carried through unchanged, `Timestamp` and `ID` empty, and `Source: otel_aggregate`. It does **not** yield per-call `ToolCallEntry` rows with timestamps.
   - **Scope (new):** the metric is exactly as unscopable as `cursor.token.usage`, so the adapter calls **`SessionEligible(sessionRequested, false, singleConversation(session))`** before emitting anything. Ineligible → `tool_calls` is **`unknown` with `UnscopedAggregateReason("cursor.tool.calls", session)`**, never an export-wide row set wearing a session's name. Eligible via the single-conversation escape → `present`, carrying `CaveatExportScopedAggregate`. Without `--session` the rows are export-scoped and say so in the spec doc, exactly as the token aggregate does. Round 4 mechanized eligibility for `tokens` only, leaving the identical defect live on `tool_calls` (V5-#4).
   Because SC-b's outcome rule reads `Status` when set — and because `Status` is never empty on these rows, which is what satisfies SC-b's comparability gate (SC-b item 14) — these `Count`-bearing rows compare to zero delta against S1b's per-call rows **for the same call set**: without `--session`, or with `--session` on a single-conversation export. That equality is asserted end to end by S7, not here.
5. **`cursor.hook.execution_complete` is removed from the read path entirely, and its four attributes are consumed by nothing (C3-#11).** R-RL-01 asks that `cursor.hook.name|.type|.outcome|.duration_ms` be corrected to their namespaced forms; the honest resolution here is **deletion, not correction** — that event describes *hook* executions, the adapter was reading it as tool calls, and after DoD 4 nothing reads it. So **no `cursor.hook.*` constant is added to `cursor_wirekeys.go`** (a constant nothing reads is dead code that guardrail 4 would then have to allow), and hook-health telemetry goes on the spec doc's "considered, not in v1.1" list beside R-CS-14 (D8). The register records R-RL-01's hook half as *not consumed*, with this line as its carrier.
6. `Probe()` on a bare `state.vscdb` reports `tokens: none` **and** `Capability.Notes["tokens"]` states the documented schema has no token data (**External evidence**, ledger §A5.4:195 — the *absence of token fields*; §A5.4:200's "Cursor is not installed on this machine" is a **Repository fact** and is the reason the schema is unverified, not the reason it lacks tokens; R-RL-03's label is split accordingly). The "with a reason" the old DoD asserted was untestable, because `CapabilityReport.Capabilities` is `map[MetricName]MetricSource` with no reason channel.
7. **`docs/profiler-spec.md` gains a "Cursor adapter" subsection under §"Adapter implementations" (`:166`)**, mirroring the Claude Code adapter's Probe / Capture / Fallback shape (`:168-190`) and stating this adapter's capability matrix in prose. **Round 2 cited an "adapter capability table" at `:135-139` — no such table exists; `:135-139` is the `ActivationEntry` struct block, which SC-a owns.** This is the real referent, it is the section that goes stale when an adapter changes, and it does not collide with SC-a's type blocks or S5's token-honesty note.

## Test approach
This slice **replaces**, not extends, the Cursor tests that pin the defect: `profiler_test.go:560` (`token_type`), `:564-565` (`skill_name`, `cursor.hook.execution_complete`-as-tool-call), `:605` (`"trigger":"keyword"` — not a value in Cursor's enum), `:626` (`Reasoning == 150`, which R-RL-01 deletes), `:644-652` (asserts `present` + `SkillName=="audit"` from wrong keys). New golden fixtures use only Wire-Reference keys — and, per D5, `*_test.go` is the second place allowed to spell `cursor.*` literals, which is what makes those fixtures writable at all. Add an assertion that the **old** keys now produce `unknown`-with-reason — never a `present` with an empty skill name, which is the current behaviour and worse than `unknown`. Add the DoD-1 grep as a test so the 12→0 claim is executed, not asserted.
**For DoD 3a (tokens):** the produced `tokens` result carries `Source: "otel_aggregate"` (not `otel`); a `--session` capture over a **multi-conversation** aggregate-only export yields `unknown` with `UnscopedAggregateReason`'s exact text; a `--session` capture over a **single-conversation** export yields `present` carrying `CaveatExportScopedAggregate`; **and an AST/grep assertion that `cursor.go` contains no assignment to `Profile.Tokens` *and* calls `ApplyTokenSelection` exactly once** — round 4 asserted only the first half, which is satisfiable by a file that produces no tokens at all (V5-#3).
**For DoD 3 + 4 (`tool_calls` scope):** a three-conversation export with `--session X` asserting `tool_calls: unknown` with `UnscopedAggregateReason("cursor.tool.calls", "X")`; the same export **without** `--session` asserting `present` and export-scoped; a single-conversation export with `--session` asserting `present` + `CaveatExportScopedAggregate`; and a log-less (metrics-only) export with `--session` asserting `unknown`, because an empty conversation set proves nothing.
**The Go test count changes here by design**; R-SA-16 is an epic-wide constraint carried in §F, and S0 is its one stated exemption.

## Next
This is a defect in merged code: it needs no Cursor installed and no user answer, only the two contract slices. It can land as a standalone fix PR to `main` (with SC-a and SC-b ahead of it) if the manager prefers, independently of whether the rest of E-CS is ever approved.

**Why SC-b is a real dependency and not an invented one (round 5).** This slice is where `Count`-bearing rows first exist. On `main`, `countToolCalls` is `len(calls)` (`compare.go:148-155`) and `successRate` divides by all rows (`:158-163`), so a three-row aggregate encoding of a six-call session compares as `count` 3 and `success_rate` 1.0 against the same session's per-call rows — the HIGH V2-#1 that SC-b item 13 exists to fix. Merging this slice ahead of SC-b would ship that defect inside the MVE for the width of a merge window, and DoD 4's zero-delta sentence would be false while it lasted. The edge costs this slice one wave of depth and buys the MVE a comparison that is not wrong.

**`profiler/cursor.go` is contended, and round 5 changed the order.** With this slice in wave 3 and S1b in wave 2, **S1b lands first and this slice rebases onto it** — the reverse of round 4's instruction, and the wave-2 S0‖S1b collision the ownership map called "the one real collision" is now gone. S1b adds a hook-spool source branch; this slice owns the `extractCursor*` helpers, `Probe`, and the OTel branch's `ApplyTokenSelection` call site. S6 (wave 4), S7 (wave 5) and S9 (conditional) write the file after both.

S6 is deliberately **not** folded in — S0 makes the adapter stop lying; S6 gives it a new capability, and extends `cursor_wirekeys.go` with the `cursor.api.request.*` keys. Folding is the manager's call, not the implementer's.
