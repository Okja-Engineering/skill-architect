# S0 — Fix the Cursor OTel adapter against the wire reference

- **Stage:** ready once SC merges
- **Owner:** unassigned
- **Branch:** none (target: `epic/skill-scope`)
- **Depends on:** **SC** (needs `ActivationEntry.Source`, `ToolCallEntry.Status`/`Count`, `MetricSource.otel_aggregate`, and `CapabilityReport.Notes` — none of which exist today)
- **Blocks:** S6, S7, **S8a** (guardrail 4 cannot go green until `cursor_wirekeys.go` exists — `cursor.go:175,182,184,186,197,224,242,262` holds 8 live `cursor.` literals)

## Goal
Stop the shipped Cursor adapter lying. Correct every OTel attribute key to its Wire-Reference form, move `tool_calls` off `cursor.hook.execution_complete` onto the `cursor.tool.calls` metric, retract the false SQLite token capability, and collect every `cursor.*` literal into one file.

## Definition of done
Rewritten at the spec gate against the **actual wire shape** (root C); every enum below is cited to its source line, not transcribed by topic:
1. Every `cursor.*` literal lives in `profiler/cursor_wirekeys.go` — one of the two places D5 allows (the other is `*_test.go`).
2. A Wire-Reference fixture yields `skill_activation: present` with a **non-empty** `ActivationEntry.SkillName` (from `cursor.skill.name`), `ActivationEntry.Source` (from `cursor.skill.source`: `unspecified|workspace|user|builtin|plugin|claude`), and a `Trigger` drawn only from the **first-party** enum `agent_read|manually_attached|skill_name_in_prompt` (D6). Both enums: **Specification**, ledger §A5.2:169.
3. `tokens` present from `cursor.token.type` (`input|output|cache_read|cache_creation` — **Specification**, ledger §A5.2:158); the dead `reasoning`/`reasoning_output` cases are **deleted** — the enum has no such member.
4. `tool_calls` reads the **`cursor.tool.calls` metric** (**Specification**, ledger §A5.2:159). That metric is a **delta counter**: no timestamp, no `cursor.conversation.id` (a *log* join key), and `cursor.tool.status` is **`success | failure | aborted`** — three values, verbatim; there is no `error`. So it yields **one row per (`cursor.tool.name`, `cursor.tool.status`) group** with `Count` set, `Status` carried through unchanged, `Timestamp` and `ID` empty, and `Source: otel_aggregate`. It does **not** yield per-call `ToolCallEntry` rows with timestamps. Because SC makes tool-call comparison encoding-invariant, these `Count`-bearing rows compare correctly against S1b's per-call rows for the same session.
5. `Probe()` on a bare `state.vscdb` reports `tokens: none` **and** `Capability.Notes["tokens"]` states the documented schema has no token data (**External evidence**, ledger §A5.4:195) — the "with a reason" the old DoD asserted was untestable, because `CapabilityReport.Capabilities` is `map[MetricName]MetricSource` with no reason channel.
6. `docs/profiler-spec.md`'s adapter capability table is updated in the same PR — the schema is normative there (`:135-139`), so changing `ActivationEntry` without it is code/doc drift by construction.

## Test approach
This slice **replaces**, not extends, the Cursor tests that pin the defect: `profiler_test.go:560` (`token_type`), `:564-565` (`skill_name`, `cursor.hook.execution_complete`-as-tool-call), `:605` (`"trigger":"keyword"` — not a value in Cursor's enum), `:626` (`Reasoning == 150`, which R-RL-01 deletes), `:644-652` (asserts `present` + `SkillName=="audit"` from wrong keys). New golden fixtures use only Wire-Reference keys — and, per D5, `*_test.go` is the second place allowed to spell `cursor.*` literals, which is what makes those fixtures writable at all. Add an assertion that the **old** keys now produce `unknown`-with-reason — never a `present` with an empty skill name, which is the current behaviour and worse than `unknown`. **The Go test count changes here by design**; R-SA-16's "34 stay green" binds every other slice.
