# S0 — Fix the Cursor OTel adapter against the wire reference

- **Stage:** ready once SC merges
- **Owner:** unassigned
- **Branch:** none (target: `epic/skill-scope`)
- **Depends on:** **SC** (needs `ActivationEntry.Source`, `ToolCallEntry.Status`/`Count`, `MetricSource.otel_aggregate`, and `CapabilityReport.Notes` — none of which exist today)
- **Blocks:** S6, S7

## Goal
Stop the shipped Cursor adapter lying. Correct every OTel attribute key to its Wire-Reference form, move `tool_calls` off `cursor.hook.execution_complete` onto the `cursor.tool.calls` metric, retract the false SQLite token capability, and collect every `cursor.*` literal into one file.

## Definition of done
Rewritten at the spec gate against the **actual wire shape** (root C):
1. Every `cursor.*` literal lives in `profiler/cursor_wirekeys.go` — the one file guardrail 4 allows (D5).
2. A Wire-Reference fixture yields `skill_activation: present` with a **non-empty** `cursor.skill.name`, a `cursor.skill.source`, and a `Trigger` drawn only from the **first-party** enum `agent_read|manually_attached|skill_name_in_prompt` (D6).
3. `tokens` present from `cursor.token.type` (`input|output|cache_read|cache_creation`); the dead `reasoning`/`reasoning_output` cases are **deleted** — the enum has no such member.
4. `tool_calls` reads the **`cursor.tool.calls` metric**. That metric is a **delta counter**: no timestamp, no `cursor.conversation.id` (a *log* join key), and `cursor.tool.status` is **tri-state**. So it yields **one row per (`cursor.tool.name`, `cursor.tool.status`) group** with `Count` set, `Status` carried through, `Timestamp` empty, and `Source: otel_aggregate`. It does **not** yield per-call `ToolCallEntry` rows with timestamps, and the DoD no longer claims it does.
5. `Probe()` on a bare `state.vscdb` reports `tokens: none` **and** `Capability.Notes["tokens"]` states the documented schema has no token data — the "with a reason" the old DoD asserted was untestable, because `CapabilityReport.Capabilities` is `map[MetricName]MetricSource` with no reason channel.
6. `docs/profiler-spec.md`'s adapter capability table is updated in the same PR — the schema is normative there (`:135-139`), so changing `ActivationEntry` without it is code/doc drift by construction.

## Test approach
This slice **replaces**, not extends, the Cursor tests that pin the defect: `profiler_test.go:560` (`token_type`), `:564-565` (`skill_name`, `cursor.hook.execution_complete`-as-tool-call), `:605` (`"trigger":"keyword"` — not a value in Cursor's enum), `:626` (`Reasoning == 150`, which R-RL-01 deletes), `:644-652` (asserts `present` + `SkillName=="audit"` from wrong keys). New golden fixtures use only Wire-Reference keys. Add an assertion that the **old** keys now produce `unknown`-with-reason — never a `present` with an empty skill name, which is the current behaviour and worse than `unknown`. **The Go test count changes here by design**; R-SA-16's "34 stay green" binds every other slice.
