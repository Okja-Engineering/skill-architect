# S0 — Fix the Cursor OTel adapter against the wire reference

- **Stage:** ready once SC merges
- **Owner:** unassigned
- **Branch:** none (target: `epic/skill-scope`)
- **Depends on:** **SC** (needs `ActivationEntry.Source`, `ToolCallEntry.Status`/`Count`, `MetricSource.otel_aggregate`, `CapabilityReport.Notes`, and **`SelectTokenSource`** — none of which exist today)
- **Blocks:** S6, S7, **S8a** (guardrail 4 cannot go green until `cursor_wirekeys.go` exists — `cursor.go` holds **12** live `cursor.` literals at `:175,182,184,186,197,216,224,234,242,250,262,271`)

## Goal
Stop the shipped Cursor adapter lying. Correct every OTel attribute key to its Wire-Reference form, move `tool_calls` off `cursor.hook.execution_complete` onto the `cursor.tool.calls` metric, retract the false SQLite token capability, and collect every `cursor.*` literal into one file.

## Definition of done
Rewritten at the spec gate against the **actual wire shape** (root C); every enum below is cited to its source line, not transcribed by topic:
1. **All 12** live `cursor.*` literals live in `profiler/cursor_wirekeys.go` — one of the two places D5 allows (the other is `*_test.go`). **Eight are event/metric names; four are inside `Unknown*Result` reason strings** (`cursor.go:216,234,250,271` — "no cursor.token.usage metric found in OTel export" and its three siblings). Round 2 counted only the eight and would have left guardrail 4 red after this slice merged. The reason strings are therefore **composed** from the same constants (`fmt.Sprintf("no %s metric found in OTel export", wireTokenUsageMetric)`), not spelled out — which is also what keeps a renamed key from drifting out of its own error message. Verification is guardrail 4's own command, run in this PR: `grep -rn 'cursor\.' profiler/ --include='*.go'` minus `cursor_wirekeys.go` and `*_test.go` returns **zero** lines.
2. A Wire-Reference fixture yields `skill_activation: present` with a **non-empty** `ActivationEntry.SkillName` (from `cursor.skill.name`), `ActivationEntry.Source` (from `cursor.skill.source`: `unspecified|workspace|user|builtin|plugin|claude`), and a `Trigger` drawn only from the **first-party** enum `agent_read|manually_attached|skill_name_in_prompt` (D6). Both enums: **Specification**, ledger §A5.2:169.
3. **`tokens` is registered as a candidate, labelled `otel_aggregate`, and this slice does not assign `Profile.Tokens` (V4-#1, D12).** The adapter reads the **`cursor.token.usage` metric**, whose `cursor.token.type` values are `input|output|cache_read|cache_creation` (**Specification**, ledger §A5.2:158) and whose attribute set carries **no conversation id** (§A5.2:158) — it is the same export-wide aggregate S6's fallback reads. Round 3 labelled it `otel` and assigned `Profile.Tokens` directly, which made this slice the **fourth** writer of a field D12 says has one, and gave the same metric two different labels depending on which slice read it. So: this slice appends `TokenCandidate{Source: otel_aggregate, SessionScoped: false}` and calls SC's **`SelectTokenSource`**, which is the only assigner. Consequences that fall out of SC's rules rather than being restated here: with `--session` the candidate is ineligible and `tokens` is `unknown` with the drop reason; when S6 later registers a per-request `otel` candidate, `otel` outranks it and nothing silently overwrites anything. The dead `reasoning`/`reasoning_output` cases are **deleted** — the enum has no such member.
4. `tool_calls` reads the **`cursor.tool.calls` metric** (**Specification**, ledger §A5.2:159). That metric is a **delta counter**: no timestamp, no `cursor.conversation.id` (a *log* join key, §A5.2:152), and `cursor.tool.status` is **`success | failure | aborted`** — three values, verbatim; there is no `error`. So it yields **one row per (`cursor.tool.name`, `cursor.tool.status`) group** with `Count` set, `Status` carried through unchanged, `Timestamp` and `ID` empty, and `Source: otel_aggregate`. It does **not** yield per-call `ToolCallEntry` rows with timestamps. Because SC's outcome rule reads `Status` when set — and because `Status` is never empty on these rows, which is what satisfies SC's comparability gate (SC item 14) — these `Count`-bearing rows compare to zero delta against S1b's per-call rows for the same session on all five figures.
5. **`cursor.hook.execution_complete` is removed from the read path entirely, and its four attributes are consumed by nothing (C3-#11).** R-RL-01 asks that `cursor.hook.name|.type|.outcome|.duration_ms` be corrected to their namespaced forms; the honest resolution here is **deletion, not correction** — that event describes *hook* executions, the adapter was reading it as tool calls, and after DoD 4 nothing reads it. So **no `cursor.hook.*` constant is added to `cursor_wirekeys.go`** (a constant nothing reads is dead code that guardrail 4 would then have to allow), and hook-health telemetry goes on the spec doc's "considered, not in v1.1" list beside R-CS-14 (D8). The register records R-RL-01's hook half as *not consumed*, with this line as its carrier.
6. `Probe()` on a bare `state.vscdb` reports `tokens: none` **and** `Capability.Notes["tokens"]` states the documented schema has no token data (**External evidence**, ledger §A5.4:195 — the *absence of token fields*; §A5.4:200's "Cursor is not installed on this machine" is a **Repository fact** and is the reason the schema is unverified, not the reason it lacks tokens; R-RL-03's label is split accordingly). The "with a reason" the old DoD asserted was untestable, because `CapabilityReport.Capabilities` is `map[MetricName]MetricSource` with no reason channel.
7. **`docs/profiler-spec.md` gains a "Cursor adapter" subsection under §"Adapter implementations" (`:166`)**, mirroring the Claude Code adapter's Probe / Capture / Fallback shape (`:168-190`) and stating this adapter's capability matrix in prose. **Round 2 cited an "adapter capability table" at `:135-139` — no such table exists; `:135-139` is the `ActivationEntry` struct block, which SC owns.** This is the real referent, it is the section that goes stale when an adapter changes, and it does not collide with SC's type blocks or S5's token-honesty note.

## Test approach
This slice **replaces**, not extends, the Cursor tests that pin the defect: `profiler_test.go:560` (`token_type`), `:564-565` (`skill_name`, `cursor.hook.execution_complete`-as-tool-call), `:605` (`"trigger":"keyword"` — not a value in Cursor's enum), `:626` (`Reasoning == 150`, which R-RL-01 deletes), `:644-652` (asserts `present` + `SkillName=="audit"` from wrong keys). New golden fixtures use only Wire-Reference keys — and, per D5, `*_test.go` is the second place allowed to spell `cursor.*` literals, which is what makes those fixtures writable at all. Add an assertion that the **old** keys now produce `unknown`-with-reason — never a `present` with an empty skill name, which is the current behaviour and worse than `unknown`. Add the DoD-1 grep as a test so the 12→0 claim is executed, not asserted. **For DoD 3:** an assertion that the produced `tokens` result carries `Source: "otel_aggregate"` (not `otel`), that this file contains **no** assignment to `Profile.Tokens` — the same property S8a's guardrail 5 enforces tree-wide — and that a `--session` capture over an aggregate-only export yields `unknown` with SC's drop reason rather than an export-wide sum. **The Go test count changes here by design**; R-SA-16's "34 stay green" binds every other slice.
