## Definition of done
1. `ActivationEntry` gains `Source string` — carries `cursor.skill.source`, whose six values `unspecified|workspace|user|builtin|plugin|claude` are **Specification** (ledger §A5.2:169, Cursor OTel Wire Reference). R-RL-05.
2. `ToolCallEntry` gains `Status string`, a **verbatim pass-through of `cursor.tool.status`, whose vocabulary is `success | failure | aborted`** (ledger §A5.2:159). *There is no `error` value, and no fourth value is added for hooks* — S1b derives all three from `postToolUse`/`postToolUseFailure` (D11) rather than widening the vocabulary. `Count int` is added for counter-derived rows. `Success bool` stays and equals `Status == "success"` when `Status` is set.
3. `ToolCallEntry` gains the identity/hierarchy fields **`ID string`**, **`GenerationID string`**, **`ParentID string`**. **`ID` and `ParentID` hold one identifier kind — a tool-call id — and only that.** The wire spelling differs by event and the spec doc states the mapping: `tool_use_id` on `preToolUse`/`postToolUse`/`postToolUseFailure` (ledger §A5.1:120,121,122), **`tool_call_id` on `subagentStart`** (§A5.1:131), which is the parent tool call of a subagent branch and therefore feeds `ParentID`. **`parent_conversation_id` is a conversation id and is barred from `ParentID`** — mixing kinds in one field is what made "chains" untestable. `Profile.SessionID` carries `conversation_id`; the chain is `SessionID` → `GenerationID` → `ID`, with `ParentID` for branches.
4. **`Attribution.Target` is *not* narrowed.** The shipped contract permits two kinds: `types.go:114` documents `Attribution` as linking "a target (tool call ID **or output**) to a skill", and `profiler-spec.md:154` spells the second kind out as "tool call ID **or output identifier**" (C4-#8 — round 3 quoted the spec doc's wording and cited it to the Go line, which is shorter). v1.1 keeps both, because `beforeReadFile` — S3's inferring event — carries **no `tool_use_id`** (ledger §A5.1:127) and could never satisfy a tool-call-only rule. The referential rule is therefore a disjunction, and it is what makes it checkable: **every `Target` either (a) resolves to some `ToolCallEntry.ID` in the same profile, or (b) is an output identifier bearing a declared scheme prefix — `file://<workspace-relative path>` is the only scheme v1.1 declares.** A bare, schemeless, unresolvable string is a contract violation — enforced by item 12, not by prose. Which form S3 emits is D11's attribution join, decided by SP1.
5. **Context-window occupancy gets its own carrier; `TokenCounts` does not grow (V3-#2, D12).** Round 2 put `ContextTokens` / `ContextWindowSize` / `ContextUsagePercent` into `TokenCounts`, which forced one `TokenResult.Source` (`types.go:23`; spec:36 "`Source` is always populated when `State == present`") to label two different quantities from two different suppliers. Context occupancy at compaction is not token *flow*. So: a new `MetricName` **`context_window`**, a new `ContextData{ContextTokens, ContextWindowSize, ContextUsagePercent}` and `ContextResult`, and a new **pointer** field `ContextWindow *ContextResult json:"context_window,omitempty"` declared **last** on `Profile` — a pointer, because a value-typed struct ignores `omitempty` and would break item 17. `TokenCounts` is left exactly as shipped. R-CS-13/R-RL-18 are representable, and each result keeps one honest source.
6. `MetricSource` gains `estimated`, `otel_aggregate`, `mcp_reported` — nine constants in total.
7. `CapabilityReport` gains `Notes map[MetricName]string` (**why** a metric is `none` — today `Capabilities` is `map[MetricName]MetricSource`, `types.go:50-55`, with no reason channel) and `Available map[MetricName][]MetricSource` (a metric may have two sources; today the second assignment silently overwrites the first, `types.go:54`).
8. **The token single-writer carrier — `Profile.Tokens` has exactly one assigner, and it lives here (V4-#1, D12).** `profiler/tokens_select.go` (new, this slice) defines:
   - `type TokenCandidate struct { Source MetricSource; Counts TokenCounts; SessionScoped bool; Caveat string }`;
   - `func SelectTokenSource(cands []TokenCandidate, sessionRequested bool) TokenResult` — **the only function in the repo that assigns `Profile.Tokens`.** Every producing slice appends a candidate; none assigns the field.
   - **The rank is total over all five flow labels:** `server_api` > `otel` > **`otel_aggregate`** > `mcp_reported` > `estimated`. It follows D3's honesty-class order (`measured_billed` > `harness_reported` > `self_reported` > `estimated`); the one intra-class tie — `otel` vs `otel_aggregate`, both `harness_reported` — breaks on **scope precision**, because `cursor.api.request` is per-request and conversation-scoped while `cursor.token.usage` is an export-wide sum (ledger §A5.2:152 vs :158). Both are the harness reporting on itself, so both outrank an MCP server's self-report. Round 3's order named four labels and left `otel_aggregate` unranked while three slices could emit it (V4-#3, C4-#2).
   - **Session eligibility, so an unscoped number can never wear a session's name:** when `sessionRequested` is true, candidates with `SessionScoped == false` are **ineligible** and are dropped with a reason. This is what makes S6 DoD 2's second case and S0's export-scoped aggregate mechanical rather than each slice's local promise.
   - **`hooks` is not an admissible token-flow label.** `SelectTokenSource` refuses a candidate whose `Source` is `hooks`, `session_data`, `sqlite`, `none` or `""`, naming the string — no hook event reports input/output/cache flow for a model call (ledger Q1:300). `hooks` appears on `context_window`, `tool_calls` and `timing`; never on `tokens`.
   - An empty or fully-ineligible candidate list yields `UnknownTokenResult` with a reason naming what was dropped and why — never a zero-valued `present` (R-SA-02).
   - A `present` result requires the winning candidate to supply both `Input` and `Output`; otherwise `unknown` with a reason naming the source and the missing field. **Lower-ranked candidates are discarded, not merged:** no field of `TokenCounts` is ever filled from a source other than the one named in `TokenResult.Source`.
9. **`RawMetricResult` gains `Caveat string json:"caveat,omitempty"` — the carrier D11's timing caveat has never had (C4-#3).** `Reason` is contractually empty when `State == present` (`profiler-spec.md:33`, retained by D2), and `CapabilityReport.Notes` describes a *capability*, not a captured value — so a `present` value with a stated caveat had nowhere to live and S1b's DoD claimed the profile stated one anyway. `Caveat` is permitted **only** when `State == present`, and its value must be one of this slice's declared constants — **a closed set, fail-closed exactly like the honesty classes**, so the field cannot become free prose:
   - `CaveatHookReceiptClock` — *"hook-receipt wall-clock, not model time; includes hook-process scheduling latency and excludes everything before the first hook fires"* (D11.1; set by S1b on `timing`, by S3 on activation timestamps);
   - `CaveatEstimatedFlow` — *"chars/4 estimate; structurally undercounts billed input and omits the system prompt, the always-loaded skill listing and the cache split"* (D12/R-CS-11; set by S5 on an `estimated` token result).
   Any other non-empty `Caveat` is a contract violation item 12 catches. The field is `omitempty` and declared last, so item 17 holds.
10. **`compare.go` gains a `context_window` comparator (V4-#4).** `CompareProfiles` (`compare.go:88-93`) has exactly five comparators — `tokens`, `tool_calls`, `timing`, `skill_activation`, `attribution` — and no `context_window`, so S7 DoD's "compared as separate metrics" had no code to bind to and D12's separation stopped at the type level. This slice adds `compareContextWindow` and `report.Metrics["context_window"]`, carrying both sides' sources and refusing a cross-class comparison like every other comparator. Adding a map key is exactly what D13's rule permits, so `ComparisonSchema` stays `v1`.
11. Every comparator carries **both** sides' sources (`BaselineSource`, `CandidateSource`) and refuses a cross-class comparison, naming both classes. Today `compareTokens` (`compare.go:106-126`) gates only on `State == present` and reports the *candidate*'s source, so an `estimated` baseline against a `server_api` candidate yields `comparable:true, source:"server_api"` and the estimate's honesty label vanishes. The existing `Source` field is **retained** and keeps meaning "the candidate's source", so no consumer breaks (D13).
12. **The referential rule gets a validator, named and called (V4-#5, C4-#3).** `profiler/validate.go` (new, this slice) defines **`func ValidateProfile(p Profile) []error`**, returning one error per contract violation: (a) an `Attribution.Target` that neither resolves to a `ToolCallEntry.ID` nor bears a declared scheme prefix (item 4); (b) a `present` result whose `Source` maps to class `none` or `unrecognized` (item 15); (c) a `ToolCallEntry.Status` outside `success|failure|aborted`; (d) a `tokens` result labelled `hooks` (item 8); (e) a `Caveat` outside the declared set, or set on a non-`present` result (item 9). **It is called, not decorative:** `CompareProfiles` runs it on both profiles and appends each violation to `ComparisonReport.Notes` (an existing field, `compare.go:83-88` — additive, no schema change). No existing fixture trips it: all four shipped adapters return `attribution: unknown` unconditionally, so rule (a) has nothing to fire on until S3 ships. Test: `TestValidateProfile`, below. S3, S5 and S1b assert against this function rather than restating the rule.
13. **Tool-call comparison is encoding-invariant, with `successes` defined exactly once (V3-#1, C3-#2).** `countToolCalls` (`compare.go:148-149`) is `len(calls)` and `successRate` (`:158-162`) divides by all rows — so once S0 emits aggregate `Count` rows, the same session compares nonzero against itself. Round 2 replaced that with **two** definitions of `successes` whose numbers disagree; round 3 replaces both with **one**:
    - a row's **outcome** is `Status` when set, else derived from `Success` (`true` → `success`, `false` → `failure`) — this is the only place the legacy field is consulted;
    - `count` = Σ `Count` (an absent or zero `Count` counts as 1); `successes` / `failures` / `aborted` = Σ `Count` over rows of that outcome;
    - `success_rate` = `successes / (successes + failures)`, and `0` when that denominator is 0 — an aborted call is neither a tool success nor a tool failure.
    **The 34 existing tests do not move as a consequence, not as a special case:** a pre-v1.1 profile has no `aborted` outcome, so `successes + failures == count` and the rate is arithmetically identical to today's.
14. **The comparability gate — what the invariant actually guarantees (V4-#8).** Round 3 claimed "zero delta **regardless of row encoding**", which its own next bullet falsified: a `Status`-less encoding of the same session yields `success_rate` 0.50 where a `Status`-bearing one yields 0.75, because the legacy fallback reads a `false` `Success` as `failure` while the hooks path calls the same call `aborted`. That is not a bug in either rule; it is two encodings that carry different information, and the contract must say so rather than promise a delta it cannot deliver. The gate:
    - `count` compares **always**, across every encoding — it needs no outcome information;
    - the four outcome figures (`successes`, `failures`, `aborted`, `success_rate`) are emitted **only when both sides carry a non-empty `Status` on every row**. If either side has a single row without `Status`, those four keys are **absent** from `baseline`, `candidate` and `delta`, and `MetricComparison.Reason` reads *"outcome figures not comparable: <baseline|candidate> encodes tool calls without Status"* while `Comparable` stays `true` for `count`. (`MetricComparison` carries one `Comparable` flag for the whole metric, `compare.go:22-29`, and the tool-call figures ride in three `map[string]any` values — so "the `success_rate` row is not comparable" is expressed by omitting the key and naming the reason, not by a second flag. Stated here so no reader expects a per-figure boolean that the shipped shape has no room for.)
    - **The invariant, restated to what the gate guarantees:** *two profiles of one session yield zero delta on `count` in every encoding, and zero delta on `successes`, `failures`, `aborted` and `success_rate` **whenever both sides carry `Status` on every row** — per-call and aggregate-`Count` encodings included.* S1b always sets `Status` (D11.2) and S0 carries `cursor.tool.status` through, so both v1.1 producers satisfy the gate; a pre-v1.1 profile does not, and now says so instead of differencing 0.75 against 0.50.
15. **Honesty classes are total and fail-closed (D3).** All nine `MetricSource` constants map to exactly one class, **including `SourceNone` (`types.go:46`) → class `none`**, **and so does the empty string**: the **five** `Unknown*Result` constructors — `UnknownTokenResult`, `UnknownToolCallResult`, `UnknownActivationResult`, `UnknownTimingResult`, `UnknownAttributionResult` (`types.go:196,216,231,246,261`) — leave `Source` at `""`, as does the **sixth `Source == ""` constructor, `ErrorTokenResult` (`types.go:201`)**, which round 3 counted among "six `Unknown*Result`" without naming it (C4-#4). So `""` is a zero value the class function really receives and it maps to `none`, not `unrecognized` — an absent provenance is not a typo'd one. A `present` result carrying `none` (from either spelling) is a contract violation. Because `RawMetricResult.Source` is a free `string`, any *other* unlisted value maps to **`unrecognized`** and `compare` refuses it, naming the string.
16. **The additive rule covers all four wire strings, not two (V4-#6).** Round 3's D1 covered `ProfileSchema` and D13 added `ComparisonSchema` — but `ExperimentSchema` (`experiment.go:14`) and `ExperimentPlanSchema` (`experiment.go:17`) are two more strictly-validated wire strings (`experiment.go:98-99,237-238` reject any other value), and **S7 adds `HookSpool` inside both**. The rule is one rule for all four: **new fields `omitempty` and declared last; new map keys only added; the string does not move.** This slice pins **four** goldens — `profile-v1-pre11.json`, `comparison-v1-pre11.json`, `experiment-v1-pre11.json`, `experiment-plan-v1-pre11.json` — and proves byte-identical re-marshal on each. It edits **no** line of `experiment.go`: marshalling the existing types into a golden needs no code change, and the golden then **fails in CI the moment S7 declares `HookSpool` wrongly**, so S7 inherits the guardrail without editing this slice's file.
17. **Every field added by items 1–9 carries `omitempty` and is declared after the existing fields of its struct** (`Profile.ContextWindow` is a pointer for the same reason). This is what makes item 16 true rather than contradictory.
18. `MetricPresent`'s doc comment stops saying "value captured from telemetry" (`types.go:12`, `profiler-spec.md:19,33`) — D2.
19. `docs/profiler-spec.md` revised to **v1.1** with a changelog, the honesty-class table (D3), the **token rank order and session-eligibility rule** (item 8), the two `Trigger` vocabularies (D6), the per-event identifier mapping (item 3), the `Attribution.Target` disjunction and its validator (items 4, 12), the outcome rule and **the comparability gate in the form item 14 states it** (items 13, 14), the two declared `Caveat` constants (item 9), D12's `context_window` carrier and its comparator, D13's comparison-report rule extended to the two experiment schemas, and a "considered, not in v1.1" note for R-CS-14 **and per-call tool durations** (D8).

## Test approach
`profiler/contract_test.go` (new, this slice's own file):
- **Golden provenance is pinned, or byte-identity proves nothing (V3-#15).** Each of the four goldens is generated **once**, by marshalling a fully-populated value through the *merge-base* source (`git show <merge-base-sha>:profiler/types.go`, `:profiler/experiment.go`), and committed **verbatim** — never hand-indented, never reordered. The producing command and the SHA go in a header comment in this test file. Then all four unmarshal and re-marshal **byte-identically** (`Marshal(Unmarshal(golden)) == golden`) → proves additivity and item 17's `omitempty` discipline across every wire string the repo has (item 16);
- a table asserting all **nine** `MetricSource` constants map to exactly one honesty class, that `SourceNone` **and `""`** map to `none`, that adding a constant without a class fails the test, and that the wire string `"wat"` maps to `unrecognized`;
- **`SelectTokenSource` (item 8), the heart of the single-writer rule:** the full rank ladder asserted pairwise — `server_api` beats `otel` beats `otel_aggregate` beats `mcp_reported` beats `estimated`, with **every** `TokenCounts` field of the winner's and **no** field retained from a discarded candidate; a `hooks` candidate **refused** by name, and likewise `session_data`, `sqlite`, `none` and `""`; an `otel_aggregate` candidate with `SessionScoped:false` **ineligible** under `sessionRequested:true`, yielding `unknown` with a reason naming the drop; an empty list yielding `unknown`; an `Input`-only winner yielding `unknown` naming the missing field;
- **`TestValidateProfile` (item 12):** a profile whose `Target` is a `ToolCallEntry.ID` passes; one whose `Target` is `file://skills/audit/SKILL.md` passes; one whose `Target` is a bare unresolvable string **fails**; a `present` result with `Source: ""` fails; a `Status` of `"error"` fails; a `tokens` result labelled `hooks` fails; an undeclared `Caveat` string fails; and a `CompareProfiles` run over a violating profile carries the violation into `ComparisonReport.Notes`;
- `compareTokens(baseline: estimated, candidate: server_api)` → `comparable:false` with a reason naming both classes; `compareTokens(baseline: "wat", candidate: hooks)` → `comparable:false` naming the unrecognized string (fail-closed); `compareTokens(baseline: hooks, candidate: otel)` → `comparable:true` reporting **both** sources;
- **`compareContextWindow` (item 10):** two `present` `context_window` results compare with both sources reported; a `context_window` result and a `tokens` result occupy **different keys** in `report.Metrics` and no code path differences one against the other;
- **encoding invariance over heterogeneous fixtures (V3-#1, item 13).** The fixture is *deliberately mixed* — a 6-call session of 3 `success` / 1 `failure` / 2 `aborted`, in **both** `Status`-bearing encodings (six per-call rows; three aggregate rows carrying `Count` 3/1/2) — compared to **zero** delta on `count`, `successes`, `failures`, `aborted` and `success_rate`, with `success_rate` = 0.75 on both sides. A homogeneous fixture cannot catch the defect this rule exists to prevent, so it is not sufficient here;
- **the gate (item 14):** a third encoding of the same session with `Status` empty and `Success` set (the pre-v1.1 shape) compared against either `Status`-bearing encoding asserts `count` delta 0, the four outcome keys **absent** from all three maps, and the reason string naming the offending side — the assertion that replaces round 3's false "regardless of row encoding" claim;
- a `Probe()`-shaped table asserting `Notes` and `Available` round-trip through JSON, and a `context_window` round-trip asserting the field is **absent** from the JSON when nil.

All **34 existing Go tests stay green** — no field is removed, no default changes, and `ValidateProfile`'s only wired call appends to an existing `omitempty` slice.
