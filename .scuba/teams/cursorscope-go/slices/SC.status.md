## Definition of done
1. `ActivationEntry` gains `Source string` — carries `cursor.skill.source`, whose six values `unspecified|workspace|user|builtin|plugin|claude` are **Specification** (ledger §A5.2:169, Cursor OTel Wire Reference). R-RL-05.
2. `ToolCallEntry` gains `Status string`, a **verbatim pass-through of `cursor.tool.status`, whose vocabulary is `success | failure | aborted`** (ledger §A5.2:159). *There is no `error` value, and no fourth value is added for hooks* — S1b derives all three from `postToolUse`/`postToolUseFailure` (D11) rather than widening the vocabulary. `Count int` is added for counter-derived rows. `Success bool` stays and equals `Status == "success"` when `Status` is set.
3. `ToolCallEntry` gains the identity/hierarchy fields **`ID string`**, **`GenerationID string`**, **`ParentID string`**. **`ID` and `ParentID` hold one identifier kind — a tool-call id — and only that.** The wire spelling differs by event and the spec doc states the mapping: `tool_use_id` on `preToolUse`/`postToolUse`/`postToolUseFailure` (ledger §A5.1:120,121,122), **`tool_call_id` on `subagentStart`** (§A5.1:131), which is the parent tool call of a subagent branch and therefore feeds `ParentID`. **`parent_conversation_id` is a conversation id and is barred from `ParentID`** — mixing kinds in one field is what made "chains" untestable. `Profile.SessionID` carries `conversation_id`; the chain is `SessionID` → `GenerationID` → `ID`, with `ParentID` for branches.
4. **`Attribution.Target` is *not* narrowed.** The shipped contract says "tool call ID **or output identifier**" (`types.go:114`, `profiler-spec.md:154`) and v1.1 keeps both, because `beforeReadFile` — S3's inferring event — carries **no `tool_use_id`** (ledger §A5.1:127) and could never satisfy a tool-call-only rule. The referential rule is therefore a disjunction, and it is what makes it checkable: **every `Target` either (a) resolves to some `ToolCallEntry.ID` in the same profile, or (b) is an output identifier bearing a declared scheme prefix — `file://<workspace-relative path>` is the only scheme v1.1 declares.** A bare, schemeless, unresolvable string is a contract violation the test catches. Which form S3 emits is D11's attribution join, decided by SP1.
5. **Context-window occupancy gets its own carrier; `TokenCounts` does not grow (V3-#2, D12).** Round 2 put `ContextTokens` / `ContextWindowSize` / `ContextUsagePercent` into `TokenCounts`, which forced one `TokenResult.Source` (`types.go:23`; spec:36 "`Source` is always populated when `State == present`") to label two different quantities from two different suppliers. Context occupancy at compaction is not token *flow*. So: a new `MetricName` **`context_window`**, a new `ContextData{ContextTokens, ContextWindowSize, ContextUsagePercent}` and `ContextResult`, and a new **pointer** field `ContextWindow *ContextResult json:"context_window,omitempty"` declared **last** on `Profile` — a pointer, because a value-typed struct ignores `omitempty` and would break item 13. `TokenCounts` is left exactly as shipped. R-CS-13/R-RL-18 are representable, and each result keeps one honest source.
6. `MetricSource` gains `estimated`, `otel_aggregate`, `mcp_reported`.
7. `CapabilityReport` gains `Notes map[MetricName]string` (**why** a metric is `none` — today `Capabilities` is `map[MetricName]MetricSource`, `types.go:50-55`, with no reason channel) and `Available map[MetricName][]MetricSource` (a metric may have two sources; today the second assignment silently overwrites the first, `types.go:54`).
8. **Honesty classes are total and fail-closed (D3).** All nine `MetricSource` constants map to exactly one class, **including `SourceNone` (`types.go:46`) → class `none`**, **and so does the empty string**: `UnknownTokenResult` and its five siblings (`types.go:196,216,231,246,261`) leave `Source` at `""`, so `""` is a zero value the class function really receives and it maps to `none`, not `unrecognized` — an absent provenance is not a typo'd one. A `present` result carrying `none` (from either spelling) is a contract violation. Because `RawMetricResult.Source` is a free `string`, any *other* unlisted value maps to **`unrecognized`** and `compare` refuses it, naming the string.
9. Every comparator carries **both** sides' sources (`BaselineSource`, `CandidateSource`) and refuses a cross-class comparison, naming both classes. Today `compareTokens` (`compare.go:106-126`) gates only on `State == present` and reports the *candidate*'s source, so an `estimated` baseline against a `server_api` candidate yields `comparable:true, source:"server_api"` and the estimate's honesty label vanishes. The existing `Source` field is **retained** and keeps meaning "the candidate's source", so no consumer breaks (D13).
10. **Tool-call comparison is encoding-invariant, with `successes` defined exactly once (V3-#1, C3-#2).** `countToolCalls` (`compare.go:148-149`) is `len(calls)` and `successRate` (`:158-162`) divides by all rows — so once S0 emits aggregate `Count` rows, the same session compares nonzero against itself. Round 2 replaced that with **two** definitions of `successes` (a `Status` path and a `Success` path) whose numbers disagree; round 3 replaces both with **one**:
    - a row's **outcome** is `Status` when set, else derived from `Success` (`true` → `success`, `false` → `failure`) — this is the only place the legacy field is consulted;
    - `count` = Σ `Count` (an absent or zero `Count` counts as 1); `successes` / `failures` / `aborted` = Σ `Count` over rows of that outcome;
    - `success_rate` = `successes / (successes + failures)`, and `0` when that denominator is 0 — an aborted call is neither a tool success nor a tool failure.
    **The 34 existing tests do not move as a consequence, not as a special case:** a pre-v1.1 profile has no `aborted` outcome, so `successes + failures == count` and the rate is arithmetically identical to today's. **Invariant: two profiles of one session yield zero delta on `count`, `successes` and `success_rate` regardless of row encoding.**
11. `MetricPresent`'s doc comment stops saying "value captured from telemetry" (`types.go:12`, `profiler-spec.md:19,33`) — D2.
12. **Every field added by items 1–7 carries `omitempty` and is declared after the existing fields of its struct** (`Profile.ContextWindow` is a pointer for the same reason). This is what makes item 13 true rather than contradictory.
13. A pre-v1.1 golden profile unmarshals **and re-marshals byte-identically** (D1). Wire `schema` stays `skill-architect/profile/v1`. **A pre-change golden *comparison report* does too** — `ComparisonSchema` (`compare.go:11`) is a real versioned wire string that D1 never covered, and D13 now states the rule it holds to.
14. `docs/profiler-spec.md` revised to **v1.1** with a changelog, the honesty-class table (D3), the two `Trigger` vocabularies (D6), the per-event identifier mapping (item 3), the `Attribution.Target` disjunction (item 4), the outcome/`success_rate` rule (item 10), D11's timing and status caveats, D12's `context_window` carrier, D13's comparison-report rule, and a "considered, not in v1.1" note for R-CS-14 **and per-call tool durations** (D8).

## Test approach
`profiler/contract_test.go` (new, this slice's own file):
- **Golden provenance is pinned, or byte-identity proves nothing (V3-#15).** `testdata/golden/profile-v1-pre11.json` is generated **once**, by marshalling a fully-populated `Profile` through the *merge-base* `types.go` (`git show <merge-base-sha>:profiler/types.go`), and committed **verbatim** — never hand-indented, never reordered. The producing command and the SHA go in a header comment in this test file. The same discipline for `testdata/golden/comparison-v1-pre11.json`. Then: both unmarshal and re-marshal **byte-identically** (`Marshal(Unmarshal(golden)) == golden`) → proves additivity and item 12's `omitempty` discipline;
- a table asserting all **nine** `MetricSource` constants map to exactly one honesty class, that `SourceNone` **and `""`** map to `none`, that adding a constant without a class fails the test, and that the wire string `"wat"` maps to `unrecognized`;
- `compareTokens(baseline: estimated, candidate: server_api)` → `comparable:false` with a reason naming both classes;
- `compareTokens(baseline: "wat", candidate: hooks)` → `comparable:false` naming the unrecognized string (fail-closed);
- `compareTokens(baseline: hooks, candidate: otel)` → `comparable:true` reporting **both** sources;
- **encoding invariance over heterogeneous fixtures (V3-#1).** The fixture is *deliberately mixed* — a 6-call session of 3 `success` / 1 `failure` / 2 `aborted`, in **both** encodings (six per-call rows; three aggregate rows carrying `Count` 3/1/2) — compared to **zero** delta on `count`, `successes`, `failures`, `aborted` and `success_rate`, with `success_rate` = 0.75 on both sides. A homogeneous fixture cannot catch the defect this rule exists to prevent, so it is not sufficient here;
- a third encoding of the same session with `Status` empty and `Success` set (the pre-v1.1 shape) asserting the legacy rate falls out of the single rule;
- **referential integrity as a disjunction (item 4):** a profile whose `Target` is a `ToolCallEntry.ID` passes; one whose `Target` is `file://skills/audit/SKILL.md` passes; one whose `Target` is a bare unresolvable string **fails**;
- a `Probe()`-shaped table asserting `Notes` and `Available` round-trip through JSON, and a `context_window` round-trip asserting the field is **absent** from the JSON when nil.

All **34 existing Go tests stay green** — no field is removed, no default changes.
