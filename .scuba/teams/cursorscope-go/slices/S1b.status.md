- **Stage:** parked on SC + S1a

## Goal
`profiler capture --harness cursor --hook-spool <f>` turns a spool into a schema-valid `Profile`. First consumer of `SourceHooks`, which exists in `types.go` and is used by no adapter today (R-SA-05). This is the read half of the old S1. It also lays the **enrichment seam** that keeps every later slice out of this slice's files.

**Rewritten at round 3.** The round-2 DoD asserted `Status`/`Success` from `afterShellExecution` — an event whose four documented fields (`command`, `output`, `duration`, `sandbox`, ledger §A5.1:124) contain **no success signal at all** — and asserted `timing: present` from hooks when **no hook event carries a timestamp**. Both are repaired below against the source-supply table in `review/revision-log-round3.md` §1: every value this slice claims is `present` from hooks now names the event and the field that supplies it, or is derived under a named Design decision with a stated caveat.

## Definition of done
1. `tool_calls` is `present` with `Source: "hooks"` from a spool. Every `ToolCallEntry` field names its supplier: `Name` ← `tool_name`, `ID` ← `tool_use_id`, both on `preToolUse`/`postToolUse`/`postToolUseFailure` (ledger §A5.1:120,121,122); `GenerationID` ← the base field `generation_id` (§A5.1:113); `Timestamp` ← the spool envelope's `received_at` (S1a DoD 6), **not** a Cursor field — see DoD 4.
2. **`Status` is derived from the events that actually carry an outcome, and is ALWAYS set (V3-#4, V3-#1, C3-#2).** The carriers are `postToolUse` and `postToolUseFailure`, not `afterShellExecution`:
   - a `tool_use_id` whose terminal event is **`postToolUse`** → `Status: "success"` (the event's existence *is* the signal; ledger §A5.1:121);
   - **`postToolUseFailure`** with `is_interrupt == true` → `Status: "aborted"` (§A5.1:122 — `is_interrupt` is the documented interrupt flag);
   - **`postToolUseFailure`** otherwise → `Status: "failure"` (§A5.1:122, alongside `error_message` / `failure_type`);
   - a `preToolUse` with **no** terminal event in the spool → `Status: "aborted"`, as a **Design decision** (D11): the call demonstrably did not complete, `aborted` is already Cursor's own word for that, and because SC's `success_rate` excludes `aborted` from its denominator the mapping is **rate-neutral** — an unterminated call can neither inflate nor deflate the rate.
   No fourth value is invented: the vocabulary stays Cursor's `success | failure | aborted` (ledger §A5.2:159). `Success` is set to `Status == "success"`. **`Status` is never left empty on this path**, which is what gives SC's `success_rate` exactly one definition and closes the 0.75-vs-0.50 divergence between per-call and aggregate encodings.
   **`afterShellExecution` supplies no outcome and is not consulted for `Status`.** `exit_code` remains a Local hypothesis (undocumented; traces only to cursorscope 0.3.7); if SP1's capture shows it, it becomes a *cross-check* on the mapping above, never its source. R-CS-15 is carried in this adapted form.
3. **Identity fields are one kind each (V3-#12, C3-#4).** `ID` and `ParentID` are **both tool-call ids** and nothing else. `subagentStart` spells its tool-call id **`tool_call_id`**, not `tool_use_id` (ledger §A5.1:131, live-confirmed): every tool-call row produced inside a subagent's conversation carries `ParentID` = that `subagentStart.tool_call_id`. **`parent_conversation_id` (§A5.1:131) is a conversation id and never enters `ParentID`** — it is consumed reader-side only, as the join key that stitches a subagent's events under the parent `conversation_id` so `--session <parent>` returns both. `Profile.SessionID` carries the root `conversation_id`.
4. **`timing` is `present` with `Source: "hooks"` under D11's stated caveat, because no hook event supplies a timestamp.** `TimingData.StartTime`/`.EndTime` come from the **first and last `received_at`** in the conversation — the stamp S1a's binary applies at hook receipt. The profile and `docs/profiler-spec.md` state the caveat verbatim: *hook-receipt wall-clock, not model time; it includes hook-process scheduling latency and excludes everything before the first hook fires.* `TotalMs` is `EndTime − StartTime` from the same stamps, so one `TimingResult` keeps one honest `Source`. **`sessionEnd.duration_ms` (ledger §A5.1:118) is Cursor-reported and is used as a test-time cross-check only** — never as a second provenance inside one result. Per-call `duration` (`postToolUse`, `postToolUseFailure`, `afterShellExecution`, `afterMCPExecution`) has **no carrier**: `ToolCallEntry` has no duration field and SC stays additive-only for what this epic needs, so it goes on the spec doc's "considered, not in v1.1" list beside R-CS-14 (D8).
5. An un-closed session is closed by a **reader-side** heuristic that sets `TimingData.EndTime` from the last event's `received_at` — no long-lived process, no in-process TTL, no leak class (R-CS-06 adapted; the original in-process form is deleted by Fork (i) and is claimed by no slice, including S11).
6. `snapshot_hash` from `CaptureOpts` lands in the `Profile` and survives `Marshal→Unmarshal→Marshal` byte-identically (R-SA-01 **and R-SA-04**).
7. `--session <conversation_id>` selects one conversation — `conversation_id` is the right `SessionID` because it is the join key to both the Admin API and Enterprise OTel (R-SA-08).
8. With no spool and no Cursor present, the adapter returns all-`unknown` and exits 0 (R-SA-13).
9. **The enrichment seam.** `profiler/enrich.go` defines `enrich(p *Profile, ev []SpoolEvent)`, which calls `enrichAttribution` and `enrichTokens`. Both are created here as **no-op stubs** in `profiler/attribution.go` and `profiler/tokens.go` — the files **S3 and S5 then own outright**. Cost: two three-line functions. Benefit: S3 and S5 run in the same wave and edit no file this slice or each other owns, so wave 3 has zero merge contention. Round 1 had S3 and S5 both listing `profiler/hooks.go`, and §F claimed they were in different waves; they were not.

**Not claimed from hooks:** `tokens` (no hook event reports input/output/cache token flow for a model call — ledger Q1:300; the only hook-derived flow number is S5's `estimated`) and `skill_activation`/`attribution` (S3, gated on SP1). This slice leaves all three `unknown`-with-reason.

## Test approach
`profiler/capture_hooks_test.go` (new, this slice's own file): a golden spool JSONL → expected `Profile` JSON comparison; a round-trip test (R-SA-01); an explicit `snapshot_hash` assertion (R-SA-04); **a subagent spool asserting `ParentID` chains rather than flattens** *and* that `ParentID` holds `subagentStart.tool_call_id` while `parent_conversation_id` appears in no `ToolCallEntry` field (R-CS-05's "subagents branch" half, now checkable and mis-mapping-proof); a two-conversation spool proving `--session` selects one, and a parent+subagent spool proving `--session <parent>` returns both; a no-Cursor/no-spool degradation test asserting all-`unknown` and exit 0 (R-SA-13); a test that `enrich` with both stubs in place leaves the profile unchanged.
**A heterogeneous `Status` fixture is mandatory, not optional:** one spool containing a `postToolUse` success, a `postToolUseFailure` with `is_interrupt: true`, a `postToolUseFailure` without it, and an orphan `preToolUse` — asserting `success`/`aborted`/`failure`/`aborted` respectively, that **no** row has an empty `Status`, and that the resulting `success_rate` matches the number SC's comparator computes for the same session encoded as aggregate `Count` rows.
**Timing:** a spool asserting `StartTime`/`EndTime` equal the first and last `received_at`; and, on a spool containing `sessionEnd`, that `TotalMs` is within a stated tolerance of `sessionEnd.duration_ms` — the assertion that gives D11's caveat teeth instead of leaving it as prose.
