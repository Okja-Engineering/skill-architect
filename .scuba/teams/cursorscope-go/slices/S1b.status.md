## Goal
`profiler capture --harness cursor --hook-spool <f>` turns a spool into a schema-valid `Profile`. First consumer of `SourceHooks`, which exists in `types.go` and is used by no adapter today (R-SA-05). This is the read half of the old S1. It also lays the **enrichment seam** that keeps every later slice out of this slice's files — and, from round 5, the seam is where the hook path's single token-assignment call site lives.

**Rewritten at round 3.** The round-2 DoD asserted `Status`/`Success` from `afterShellExecution` — an event whose four documented fields (`command`, `output`, `duration`, `sandbox`, ledger §A5.1:124) contain **no success signal at all** — and asserted `timing: present` from hooks when **no hook event carries a timestamp**. Both are repaired below against the source-supply table in `review/revision-log-round3.md` §1.

**Corrected at round 4 (C4-#3, V4-#9).** DoD 4 claimed "the profile states the caveat verbatim" when no field could hold it: `RawMetricResult` is `{State, Reason, Source}` and `Reason` must be empty when `State == present` (`profiler-spec.md:33`). ## Definition of done
1. `tool_calls` is `present` with `Source: "hooks"` from a spool. Every `ToolCallEntry` field names its supplier: `Name` ← `tool_name`, `ID` ← `tool_use_id`, both on `preToolUse`/`postToolUse`/`postToolUseFailure` (ledger §A5.1:120,121,122); `GenerationID` ← the base field `generation_id` (§A5.1:113); `Timestamp` ← the spool envelope's `received_at` (S1a DoD 6), **not** a Cursor field — see DoD 4.
2. **`Status` is derived from the events that actually carry an outcome, and is ALWAYS set (V3-#4, V3-#1, C3-#2).** The carriers are `postToolUse` and `postToolUseFailure`, not `afterShellExecution`:
   - a `tool_use_id` whose terminal event is **`postToolUse`** → `Status: "success"` (the event's existence *is* the signal; ledger §A5.1:121);
   - **`postToolUseFailure`** with `is_interrupt == true` → `Status: "aborted"` (§A5.1:122 — `is_interrupt` is the documented interrupt flag);
   - **`postToolUseFailure`** otherwise → `Status: "failure"` (§A5.1:122, alongside `error_message` / `failure_type`);
   - a `preToolUse` with **no** terminal event in the spool → `Status: "aborted"`, as a **Design decision** (D11): the call demonstrably did not complete, `aborted` is already Cursor's own word for that, and because SC-b's `success_rate` excludes `aborted` from its denominator the mapping is **rate-neutral** — an unterminated call can neither inflate nor deflate the rate.
   No fourth value is invented: the vocabulary stays Cursor's `success | failure | aborted` (ledger §A5.2:159). `Success` is set to `Status == "success"`. **`Status` is never left empty on this path** — which is what will put a hooks-sourced profile inside SC-b's comparability gate (SC-b item 14), so it carries the four outcome figures rather than having them withheld.
   **`afterShellExecution` supplies no outcome and is not consulted for `Status`.** `exit_code` remains a Local hypothesis (undocumented; traces only to cursorscope 0.3.7); if SP1's capture shows it, it becomes a *cross-check* on the mapping above, never its source. R-CS-15 is carried in this adapted form.
3. **Identity fields are one kind each (V3-#12, C3-#4).** `ID` and `ParentID` are **both tool-call ids** and nothing else. `subagentStart` spells its tool-call id **`tool_call_id`**, not `tool_use_id` (ledger §A5.1:131, live-confirmed): every tool-call row produced inside a subagent's conversation carries `ParentID` = that `subagentStart.tool_call_id`. **`parent_conversation_id` (§A5.1:131) is a conversation id and never enters `ParentID`** — it is consumed reader-side only, as the join key that stitches a subagent's events under the parent `conversation_id` so `--session <parent>` returns both. `Profile.SessionID` carries the root `conversation_id`.
4. **`timing` is `present` with `Source: "hooks"` and `Caveat: CaveatHookReceiptClock`, because no hook event supplies a timestamp (C4-#3).** `TimingData.StartTime`/`.EndTime` come from the **first and last `received_at`** in the conversation — the stamp S1a's binary applies at hook receipt. The caveat *travels in the profile*, in SC-a's closed-set `RawMetricResult.Caveat` field, whose declared text is *"hook-receipt wall-clock, not model time; includes hook-process scheduling latency and excludes everything before the first hook fires"*; `docs/profiler-spec.md` states the same text once, as the constant's definition. Round 3 said "the profile states the caveat verbatim" with no field able to hold it — a claim about the artifact that the artifact could not carry. `TotalMs` is `EndTime − StartTime` from the same stamps, so one `TimingResult` keeps one honest `Source`. **`sessionEnd.duration_ms` (ledger §A5.1:118) is Cursor-reported and is used as a test-time cross-check only** — never as a second provenance inside one result. Per-call `duration` (`postToolUse`, `postToolUseFailure`, `afterShellExecution`, `afterMCPExecution`) has **no carrier**: `ToolCallEntry` has no duration field and SC-a stays additive-only for what this epic needs, so it goes on the spec doc's "considered, not in v1.1" list beside R-CS-14 (D8).
5. An un-closed session is closed by a **reader-side** heuristic that sets `TimingData.EndTime` from the last event's `received_at`, triggered by the occurrence of `sessionEnd` (`final_status`, :118) or `stop` (`status`, :135) or, failing both, by end-of-spool — no long-lived process, no in-process TTL, no leak class (R-CS-06 adapted; the original in-process form is deleted by Fork (i) and is claimed by no slice, including S11).
6. `snapshot_hash` from `CaptureOpts` lands in the `Profile` and survives `Marshal→Unmarshal→Marshal` byte-identically (R-SA-01 **and R-SA-04**).
7. `--session <conversation_id>` selects one conversation — `conversation_id` is the right `SessionID` because it is the join key to both the Admin API and Enterprise OTel (R-SA-08). **A hook spool needs no eligibility rule:** every hook event carries `conversation_id` as a base field (§A5.1:113), so every hook-derived row is session-scoped by construction. SC-a item 8's unscopable-aggregate rule binds the OTel path (S0, S6), not this one — stated here so the asymmetry is a fact about the surfaces, not an omission.
8. With no spool and no Cursor present, the adapter returns all-`unknown` and exits 0 (R-SA-13).
9. **The enrichment seam.** `profiler/enrich.go` defines `enrich(p *Profile, ev []SpoolEvent, cands *TokenCandidates, sessionRequested bool)`, which calls `enrichAttribution` and `enrichTokens`. Both are created here as **no-op stubs** in `profiler/attribution.go` and `profiler/tokens.go` — the files **S3 and S5 then own outright**. Cost: two three-line functions. Benefit: S3 and S5 run in the same wave and edit no file this slice or each other owns, so their wave has zero merge contention.
10. **This slice registers no token candidate, owns the hook branch's one call site, and asserts the consequence (V4-#1, V5-#3, D12).** No hook event reports input/output/cache-read/cache-creation flow for a model call (ledger Q1:300), so the hooks path `Add`s **zero** entries to the `*TokenCandidates` accumulator SC-a defines. What this slice does own is **one line — the last statement of `enrich()` in `profiler/enrich.go`: `ApplyTokenSelection(p, cands.List(), sessionRequested)`.** It is placed after `enrichAttribution` and `enrichTokens` deliberately: that is what lets **S5** (`tokens.go`, `estimated` + `mcp_reported`) and **S9** (`cursor_admin_api.go`, `server_api`) register candidates from inside the seam without adding an assignment or a second call site of their own. With no producer merged, the list is empty and `Profile.Tokens` is `unknown` with SC-a's empty-list reason — a stated value, not a zero value left behind. **This slice contains no assignment to `Profile.Tokens`**; the write lives in SC-a's `tokens_select.go`, the only file S8a's guardrail 5(a) allowlists. `skill_activation` and `attribution` are likewise left `unknown`-with-reason (S3, gated on SP1).

## Test approach
`profiler/capture_hooks_test.go` (new, this slice's own file): a golden spool JSONL → expected `Profile` JSON comparison; a round-trip test (R-SA-01); an explicit `snapshot_hash` assertion (R-SA-04); **a subagent spool asserting `ParentID` chains rather than flattens** *and* that `ParentID` holds `subagentStart.tool_call_id` while `parent_conversation_id` appears in no `ToolCallEntry` field (R-CS-05's "subagents branch" half, now checkable and mis-mapping-proof); a two-conversation spool proving `--session` selects one, and a parent+subagent spool proving `--session <parent>` returns both; a no-Cursor/no-spool degradation test asserting all-`unknown` and exit 0 (R-SA-13); a test that `enrich` with both stubs in place leaves the profile unchanged **apart from `Tokens`, which `ApplyTokenSelection` sets to `unknown`-with-reason**.
**A heterogeneous `Status` fixture is mandatory, not optional:** one spool containing a `postToolUse` success, a `postToolUseFailure` with `is_interrupt: true`, a `postToolUseFailure` without it, and an orphan `preToolUse` — asserting `success`/`aborted`/`failure`/`aborted` respectively, and that **no** row has an empty `Status`. **Round 5 removed the clause that also asserted the `success_rate` this session yields under the aggregate encoding:** that is a claim about `compare.go`, which is SC-b's file, and it would have made this slice depend on SC-b for a number SC-b's own heterogeneous fixture already pins and S7 proves across two real adapters (V5-#15). What belongs here is the row-level derivation; what belongs there is the arithmetic over it.
**Timing:** a spool asserting `StartTime`/`EndTime` equal the first and last `received_at`; an assertion that `Timing.Caveat == CaveatHookReceiptClock` and that the value survives round-trip (DoD 4 — the caveat is now checkable, where round 3's prose was not); and, on a spool containing `sessionEnd`, that `TotalMs` is within a stated tolerance of `sessionEnd.duration_ms`.
**Tokens (DoD 10):** an assertion that `tokens` is `unknown` with SC-a's empty-candidate reason; that no `TokenResult` on this path ever carries `Source: "hooks"`; **an AST/grep assertion that this slice's files contain no assignment to `Profile.Tokens` *and* that `enrich.go` calls `ApplyTokenSelection` exactly once, as its last statement** (V5-#3 — round 4 asserted only the negative half, which an inert file satisfies); and that `ValidateProfile` returns no errors for the produced profile.
