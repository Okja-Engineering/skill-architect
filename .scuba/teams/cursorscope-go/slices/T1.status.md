## Goal
Surface the real BPE token numbers that already flow into `audit.json` but are never shown, and add a context-budget scoring dimension. The only token number in the whole plan that depends on nothing the user has to own.

## Definition of done
`audit.json` gains `summary.token_cost{body, references, total, always_loaded_chars}` derived from `.spec.token_counts`; the evaluation matrix gains a **Context budget** dimension scoring `description` + `when_to_use` ≤ 1,536 chars and `SKILL.md` ≤ 500 lines; the `char/4` fallback is used **only** when `skill-validator` is absent and is labelled estimated.

## Test approach
Extend `tests/test_f02.sh`, which already asserts `.spec.token_counts` exists (`:100`), with:
- assertions on each new `summary.token_cost` key, against a fixture skill whose real counts are known;
- a fixture skill exceeding the 1,536-char `description`+`when_to_use` cap scores **0** on the new dimension, and one just under it scores full — the boundary proven from both sides;
- a run with `skill-validator` masked off `PATH`, asserting the `char/4` fallback engages **and** that the output is labelled estimated, so a fallback number can never be read as a BPE number.

## Grounding
- **Repository fact:** `audit-report.sh:36` already runs `skill-validator check -o json` and passes the whole body through as `.spec`; `tests/test_f02.sh:100` already asserts `.spec.token_counts` exists. The work is surfacing it, not producing it.
- **Repository fact:** `skill-validator check -o json` emits `.token_counts.files[]{file, tokens}` and `.token_counts.total`; `analyze content -o json` does **not**.
- **External evidence** (ledger §A4): that those counts are real `o200k_base` BPE is skill-validator's documented behaviour, not something this repo measured — the prior "Repository fact" label overstated it.
- **Repository fact (measured):** `skills/skill-audit` totals 4,030 tokens — 1,814 body, 2,216 references, i.e. 55% of its token mass sits behind progressive disclosure.
- **Specification:** Claude Code truncates `description` + `when_to_use` at 1,536 chars in the always-loaded listing and recommends `SKILL.md` under 500 lines.
- **External evidence** (ledger §B1): `skillListingBudgetFraction` defaults to **0.01**. This is *not* on the public skills doc page — it is a **fraction of the context window** (~200K reference), not an absolute char budget, so it informs the dimension's framing but must not be scored as a fixed number.
